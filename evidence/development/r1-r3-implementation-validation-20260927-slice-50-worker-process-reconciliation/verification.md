# Slice 50 — Windows Worker process recovery

Date: 2026-09-27

## Scope

Provider and deterministic WorkerSession processes on Windows now use globally named Job Objects derived from the session ID, with the default ACL restricting access to the creating account. The process is created suspended inside the Job Object through `PROC_THREAD_ATTRIBUTE_JOB_LIST`, eliminating the uncontained create/assign crash window. Kernel records the host/containment profile before launch, confirms it during attachment, and can re-open, terminate, and verify the process tree after restart. Successful reconciliation closes only the old WorkerSession; it does not reset the Task or replay its Mission start. Stop failures, including pre-activation and no-process startup cleanup, retain adapter ownership for retry; process-stop confirmation, same-PID attachment and no-process finalization are idempotent. Adapters replay saved process and host-stop proofs after ambiguous confirmation commits, including host-reaper receipt readback. Deterministic launch failures and local zero-turn qualification failures also retain their process owner for retry. A nil launch environment becomes an explicit empty environment, and Windows `Run` preserves exit/cleanup errors while `WaitError` retains both nonzero exit codes and cleanup failures.
