# Slice 155 — CAP-13–19 MCP discovery and trust-boundary audit

## Source findings

| Scenario | Current boundary | Remaining qualification or gap |
| --- | --- | --- |
| CAP-13 repository/native harness discovery | Worker launch assigns a session-specific `HOME` and `CODEX_HOME`; the native model gets only its pinned Polis tool surface. Skill and stdio MCP packages are explicitly imported, then separately qualified, approved and Employee-bound. No ambient repository/user MCP config is wired into Worker tool registration. | Native host/harness qualification was not run. If project-level discovery is added, it needs a candidate-only path and must never launch unapproved entries. |
| CAP-14 stdio process boundary | Only the concrete `AppContainerSandbox` owner can launch; process specs pin complete package bytes, command, entry point and arguments and require deny-all networking. Runtime observation performs discovery/list only. | This Termux host cannot establish Windows AppContainer filesystem or WFP policy evidence. The repository evidence records native AppContainer tests but no installed WFP policy; external Windows host qualification remains open. |
| CAP-15 Streamable HTTP endpoint boundary | Canonical HTTPS only; proxy and redirects disabled; TLS verifies hostname; every dial re-resolves DNS and rejects private/special-use destinations. Endpoint and schema are pinned to an approved runtime record. | OAuth/endpoint credentials and independent remote identity qualification are not implemented. No real endpoint/account was contacted. |
| CAP-16 protocol/profile compatibility | Stdio and Streamable HTTP have separate immutable profile identifiers, both pin `2026-07-28`, and do not negotiate/fallback into a legacy profile. Unsupported wire shapes fail closed. | Compatibility with other protocol versions and real third-party SDKs is not qualified. |
| CAP-17 paging, duplicate names and cross-employee state | Tool names are disambiguated by a `capability_id` and exact schema digest; only one MCP tool set is admitted in one Worker context, and process state is per WorkerSession. Duplicate names inside one catalog are rejected. | Both stdio and HTTP currently reject any `nextCursor`. They refuse paginated catalogs instead of completing full bounded discovery. Slice156 will implement bounded page traversal and aggregate validation. No shared catalog cache was found in these call paths. |
| CAP-18 server-provided behavior hints | The canonical digest pins the raw definition, but only name, description and input schema are projected to the model. `readOnlyHint`/`idempotentHint` do not change Polis authorization or retry policy. Tool results are untrusted, and ambiguous calls remain `outcome_unknown`. | Frozen CAP-18 execution remains open. |
| CAP-19 tool/schema mutation | MCP qualification pins a canonical digest over sorted tool definitions; runtime and Employee binding/approval refer to the exact version/digest. Worker calls rediscover and compare the digest before dispatch; drift blocks the call. Polis-native tool surfaces also have separate versioned qualification/digest gates. | Frozen CAP-19 execution remains open; mutation/requalification E2E was not run. |

## Verification scope

- Read-only source inspection of `internal/provider/codex_runtime.go`, `internal/runner`, `internal/mcptransport`, `internal/mcpowner`, `internal/kernel/mcp_worker_context.go`, `internal/kernel/mcp_tool_calls.go`, `internal/control/stdio_mcp_worker.go` and the MCP qualification/observation paths.
- Compared expected behavior to frozen `CAP-13`–`CAP-19` entries in `spec/design-v0.4.5/tests/capability_scenario_catalog.json` and the `CAP` boundary table in `spec/design-v0.4.5/ARCHITECTURE.md`.
- Verified against the pinned [MCP 2026-07-28 tools specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/tools.mdx) and [Streamable HTTP transport specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/transports/streamable-http.mdx): tool listing has cursor pagination, and the HTTP profile requires per-request metadata, JSON/SSE handling and parameter-derived header behavior.
- No source code, database, endpoint, credentials, native MCP process, tests or frozen scenario was exercised in this audit.
- Frozen CAP-13–19 execution states remain `not_run`; no external host/account qualification is claimed.
