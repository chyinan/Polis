43. 交错场景复核与审核收敛规则

43.1 审核目标不是“写到没有新点子”

当前范围：单人管理、固定组织、Go/PG 单控制面、有限合格执行链、正式员工操作、跨模型接班、休眠与授权内工作、企业工作台、QQ 官方主动接管通知，以及本轮明确的文件/Skills/MCP 能力。没有新增自动人事、多机集群、办公室、实盘交易或任意平台自动运营。

可用的收口标准：当前冻结范围内，没有未处置的已知设计阻塞；每项已发现问题有明确规则、验证位置和失败行为。 不能据此声称没有未知遗漏、没有实现错误、任意模型都可靠。静态评审、人工推演、schema 检查、模拟状态机、真实 PG/工具、真实 QQ/模型和长跑是不同证据等级。

本轮记录在 audit/FINDINGS.json：disposition=patched_in_spec 只表示文档已修订；verification_status=not_run 明确还未在拟议产品上验证。audit/OPEN_GATES.json 保存待实测/待配置门，不把它们删掉换一个好看的“零问题”数字。阶段 G0 允许为证实这些规则开发小原型；需要强保证的执行模式必须在相应 Gate 通过以后开放。

43.3 PG 认领不能破坏自己规定的锁顺序

统一采用已定义的锁序，但明确：候选选择不等于认领。 首版调度器先做有界、无行锁的候选 ID 读取；再在短事务中按顺序锁定所需记录，重验候选仍为 ready、使命/授权/资源仍有效，然后一次性认领、预留并写 outbox。候选在两步之间被他人取走时正常跳过，不创建半个 Attempt。

锁族的初始顺序为：作用域/生命周期 guard → 授权 guard → 预算 → 实际资源 → 员工调度 → Task/Attempt → 消息/责任 → 产物/pin → 公司事件流头；同族按稳定 ID 排序。只锁本命令所需集合；发现更早锁族需求时回滚重启，不反向补锁。审查器检查实际 SQL 与外键/触发器附带锁，不把表面调用顺序当完整证明。PG 官方也要求用一致顺序减少死锁；仍要有界重试纯数据库事务。Q05

SKIP LOCKED 保留给只认领 outbox/投递记录等适用路径。禁止先锁住 Task，再在同一事务取得更早的政策/预算锁；不能称“选完之后再按统一顺序”就抹掉先前持有的锁。需要队列吞吐优化时另以真实死锁/饥饿/预算实验修改，首版不为了并发数字提前复杂化。

43.4 恢复到过去的数据不能恢复过去的执行权

区分长期 installation_id、DB 历史中的 employee_epoch，以及本次运行的 runtime_incarnation。控制面安全启动/接管时生成新的不可预测 incarnation；在只读恢复模式内轮换短期执行会话与许可签发状态。不能仅靠从旧备份读出的递增整数判断新旧执行者。

员工调用、监督器授权和派发许可同时绑定 incarnation、employee_epoch、attempt 与当前 grant。换 incarnation 后旧凭据/许可不可执行；仍存活的 OS 写者必须另行停止/隔离，换 token 不能撤回其已有文件描述符。浏览器流标明 data lineage/incarnation 变化并重新取快照，不把恢复后较小的 company_seq 当成当前事件连续倒退。

原生会话是上下文优化，不自动携带旧工具权限。权限降低、数据目的地变化或恢复代际变化后，后端不能证明确实收回了原生工具能力，就停止该会话、走中立接班；不得用旧 resume 重新引入已经撤销的能力。

整机备份导入不激活通知 capsule、不重放业务 outbox；删除/撤销清单可取得且已核对才加载相关敏感资料。清单也损坏或无法确定是否最新时，进入暂停检查并要求受信人重新划定允许范围，不承诺凭一份旧备份恢复“最新撤权”。在第二台主机导入也不能证明第一台已停止；首版禁止将克隆恢复当成双机并行，实际目标重新绑定前需确认旧安装停止/隔离。

43.5 写回目标必须仍是刚才被验收的那条基线

软件领域验收绑定 (candidate_commit, integration_base, integrated_commit, verifier_revision, environment_fingerprint)。固定候选以后目标分支也可能变化；最后的更新必须是比较并交换，而不是“检查一次然后无条件推送”。

首个本地受控集成入口在专用 bare 仓库使用固定 direct ref 与期望旧 OID 的更新，例如概念操作 git update-ref <allowed-ref> <verified-new-oid> <expected-old-oid>。参数由程序通过 argv 传入，ref、对象类型、完整 OID、路径及权限先验证；不是让模型组 shell 文本。Git 文档明确支持比较当前 ref 与 old-oid 后更新。Q06

旧 OID 不匹配时标 integration_base_changed，重新组合和验证；不能 force push 或把旧测试结果移到新组合。若未来远端不提供可验证的条件更新路径，则不宣称同等自动合并保障，需限定资源唯一写者或收缩该功能。运行时独占记录也不能阻止一个外部人手动推仓库，仍需目标端条件检查。

审查环境只读候选 + 独立 scratch。验收工具/基准由可信流程固定，不接受被审仓库自行改写门槛；验证缓存要按信任级别隔离，不让作者写入的共享编译缓存成为独立验收唯一依据。采用可写工作副本进行测试的工具必须明确记录输入复制与哈希，不能把“验证前后同名目录存在”当不可变证据。

43.6 等待是可执行条件，不是“有未读就一直醒”

每个 blocked/yield 记录结构化 WaitCondition：等待种类、关联资源/对象、可核对的满足条件、责任人或外部来源、到期策略与允许的唤醒原因。没有恢复条件的自由文本不构成无限等待许可；运行时拒绝或转成有界澄清任务。

新消息不等于任务已可执行；未满足的依赖、仅供参考信息、相同消息重复观察，不要因为它一直在 inbox 就重复启动模型。wait 与 signal 的版本共同参与准入。员工等待同事时先保存进度并交还推理槽；写资源另行排空/保留/隔离，不能为了释放算力让另一个写者接手半写文件。

程序维护的是显式任务依赖和资源等待关系，检查无人负责事项、A/B 等待环和资源饥饿；不承诺自动推断所有语义依赖。现有固定规划岗只有在协调任务确实可执行、预算允许时被唤醒；没有可行路径就形成可行动 blocker，不能用“再问一次同事”无限互相唤醒。

43.7 背压先保护控制与证据，不静默丢业务

为控制命令/回执、关键任务/责任事件、普通业务通知、原始模型日志分别设容量与优先级。列表分页、出站/入站正文上限、工具输出上限和公司存储限额在部署配置固定，缺值不能无限制。heartbeat 存活时间和计划进展时间分开记录。

进入压力状态时先停止新的非必要工作和原文采集，可合并 FYI/重复日志、标明截断并记录指纹；不能删除已经承诺持久接受的 Action、Obligation 或验收记录来腾空间。保留急停、在途核对、token 刷新和收尾的普通程序容量，不让海量 stdout 阻塞管理路径。关键记录不能落盘时不确认成功，停止新副作用并用监督覆盖所允许的方式告警。

时钟用于两类事情：日历计划用明确时区与 UTC occurrence；运行中的超时/许可剩余寿命用单调经过时间约束。墙钟显著跳变、跨重启旧 TTL 或后台定时器不确定时，按资格记录保守核对，不自动延长预算/授权期限。失效判定的具体阈值是待实测参数，不伪称已在所有宿主验证。

43.8 开工范围、证据门与迭代纪律

第一条小闭环的规范要先有：启动固定规划员、员工工具回执、一个真实横向请求、任务产物和独立验收；然后加入强制接班与 QQ 通知资格。不是等全部未来能力证实后才允许写第一行代码，也不是拿 UI 演示替代这些实验证据。

实验前固定 fixture 版本、预期断言、对照配置、预算/时间窗、失败与停止规则。真实调用只有得到授权后才执行；指标阈值必须在实验前填写，未填写不能事后挑结果宣布通过。长期价值用同基础设施的强单体作对照；多 Agent 多花钱却无收益时保留单体路径。

audit/OPEN_GATES.json 是剩余证据/配置输入，而非无穷功能待办。进入某个风险阶段只要求该阶段适用的 Gate，不把低风险静态排版卡在尚未购买的模型额度上；不适用要写理由并限制公开支持范围。待实现、待实测、已延期和未知风险分别统计，不能合并为一个“0 bug”。

复核结论的允许措辞：本次列出的设计问题已落实规则与测试；尚未进行运行验证。禁止措辞：审核到完全没有遗漏、所有后端均可无损换脑、QQ 在所有故障下必达。
