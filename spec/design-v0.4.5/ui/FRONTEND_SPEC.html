37. 前端产品方向与视觉系统

37.1 本轮已确认的审美取舍

主工作台以 Paperclip 式专业、克制的企业风为视觉和信息组织参照；不是像素经营游戏，也不是 3D 办公室模拟器。 “企业风”在本项目指明确层级、适度密度、可持续阅读与可追溯操作，不指满屏蓝色表格、发光大屏或装饰性指标。

参照或表现方式 本版决定 不随之引入的内容
Paperclip 主要视觉方向及公司→目标→任务→成员的导航启发 不复制品牌、整套源码、业务权限或依赖树；不把其后端当本项目底座
ClawPort 只保留组织关系、成员入口、详情互跳等交互思想 不采用其整套视觉皮肤，也不引入 OpenClaw/Next.js 依赖
Claw3D 不作为当前实施或视觉方向 不增加 Three.js、React Three Fiber、人物模型或场景编辑器
办公室视图 延期，画风未定；以后可作为同一状态的替代视图 首版没有办公室导航占位、自动演出、寻路、碰撞、工位数据库或 WebGL 依赖
组织与协作关系 先用名单、责任表和上下游列表表达；图形视图按实际需求后加 不用拖动节点偷偷改变岗位、权限、员工数或任务依赖

以上偏好来自维护者确认；具体颜色、间距和组件尺寸是本版拟议实现基线，不冒充已经得到最终视觉验收。Paperclip 的公开 UI 包采用 React/Vite/TanStack Query 等，也同时依赖自己的 shared/adapter 包；本轮只定向读取了该依赖声明，不能据此认定复制目录即可独立接入 Go。U01

37.2 首屏设计原则

打开公司后，第一屏应该依次回答：使命是什么；最近有没有有效进展；哪里阻塞或需要决策；资源是否接近边界。 员工数量、累计消息和 token 不应占据最大视觉层级。员工可以休眠，不制造“公司始终很忙”的错觉。

页面使用低饱和中性背景、轻边界、单一强调色和明确的文字层级。关键警告才使用警示色；普通等待和休眠不是红色故障。保留足够空白，但不把每个字段放进一张巨大卡片。正文和表格主要 14–16px，辅助说明不靠极小字号节省空间。

禁止作为默认设计：大面积霓虹渐变、玻璃炫光、持续脉冲、无数据依据的环形完成率、满屏模型 Logo、巨型员工头像、无意义“今日算力战报”、强迫用户逐个打开聊天确认进度。

37.3 设计 token：统一维护，不让页面各自选色

样式采用 语义 CSS 变量 + CSS Modules。组件只读取 token；新增页面不自造第二套圆角、阴影和状态色。Vite 原生支持 CSS Modules；不为这套视觉再引入运行时 CSS-in-JS 服务或另一套构建系统。U10

Token 类别 初始实现值 / 规则 用途
画布 / 容器 / 次级容器 浅色 #F7F8FA / #FFFFFF / #F1F3F5 分层而不堆阴影
主要 / 次要文字 浅色 #17212B / #526171 次要文字仍需可读
强调 / 链接 浅色 #264E73，强调按钮文字白色 当前页、主要动作和链接，不混为成功
分隔 / 控件边界 浅色 #DCE2E8 / #7B8794 装饰分隔线与必要控件边界分开，不对弱分隔线宣称交互对比合格
成功 / 警示 / 危险 / 信息 #17623B / #8A4B08 / #B42318 / #245B9A，配低饱和底色 必须同时有文字或图标，不只靠颜色
间距 4 / 8 / 12 / 16 / 24 / 32 / 48px 用一套节奏，不随页面任意加值
圆角 控件 6px、面板 8px、对话框 12px 标签可用胶囊；不让所有矩形都变成胶囊

浅色、深色及跟随系统使用相同语义变量，深色不是反色滤镜。浅色首先打样；深色和系统主题在首版 UI 验收中覆盖。主题选择可以保存到本地偏好；客户资料、消息和账号凭据不能因此一起持久化到浏览器。

ui/design-tokens.json 是候选 token 源，ui/tokens.css 是生成示例。调色只改这一处，并重跑声明的文字/控件对比配对。对比检查只覆盖列出的色对，不等于整套应用已符合无障碍标准。

37.4 组件制度：行为复用，视觉自主

前端在既定 React/TypeScript/Vite/TanStack Query 上，补定 React Router 声明式路由、按需 Radix Primitives、Lucide 图标、CSS Modules。React Router 可与 Vite 的 SPA 组合，选择此模式不引入其全栈/SSR 服务。U03 Radix 提供无样式交互原语，适合作为对话框、菜单、Tabs 的基础；正确标签、对比与业务流程仍由本项目负责。U02 Lucide 采用按需导入的内联 SVG，不动态下载整套图标。U09

统一组件 最小内容 / 行为 禁止的变体
AppShell / ScopeHeader 固定导航、集团/公司位置、模式与数据连接状态 公司切换只换标题、不换数据作用域
PageHeader 页面标题、简述、主要动作、筛选 同一屏到处都是一级主按钮
EmployeeIdentity 工号、岗位、公司；小头像可选 工号因会话更换而变化；远程头像跟踪默认加载
StatusBadge / Freshness 状态文字、图标、观测时间、来源 绿色代表一切正常；只用一个在线点
ResourceAmount 单位、币种、口径、截止时间；未知单独显示 null→0；把 token 当金额；前端重算可用预算
EvidenceLink / RevisionTag 精确产物/规则版本与证据入口 “最新通过”覆盖具体被审版本
OperationPanel 已受理、执行阶段、结果、未知项与回执 一收到 HTTP 202 就显示已完成
DataTable / EmptyState 清楚列名、筛选、分页、空/失败/无权限区别 后端没接时硬编码经营数据填满卡片
DecisionDialog 公司、对象、影响范围、待确认版本、取消入口 默认勾选提权或不展示在途动作

原生表格、按钮、表单优先；复杂焦点行为交给一个基础原语体系。首版不混装 Ant Design、MUI、Radix Themes、Base UI、shadcn 全套皮肤。不是这些方案不好，而是避免多套行为和 token 同时维护。表格/图表后续有明确复杂需求再通过 ADR 选型，不为一个数字卡引入大图表引擎。

38. 工作台信息架构与页面蓝图

38.1 集团和公司有不同的导航作用域

集团首页是组合总览，公司首页是当前使命的工作台。 不把所有公司的日志合成全局群聊。导航采用固定侧栏和清楚的公司切换器；切到新公司后保留“页面种类”可以，但对象、筛选、未提交操作必须重新按作用域核对。

作用域 入口 应回答的问题 首版交付
集团 / 公司总览 哪些公司在推进、等待、需要我？总资源怎样？ G1
集团 /companies/new 我怎样创建固定员工和明确授权的团队？ G1
集团 /group/resources、/group/settings 共享账号与集团上限是什么？ G1 基础，G3 完善
公司 /companies/:companyId/overview 当前目标、最近有效进展、阻塞和下一里程碑？ G1
公司 …/missions/:missionId 目标与策略有什么变化？验收依什么？ G1/G3
公司 …/tasks、…/tasks/:taskId 谁在做什么，等待什么，成果是否被验证？ G1/G3
公司 …/employees、…/employees/:employeeId 固定员工档案、模型、责任和接班情况？ G1/G2
公司 …/activity 哪些重要协作、决定和异常刚刚发生？ G1/G2
公司 …/resources 已结算、预留、未知消耗与存储边界？ G1/G3
公司 …/evidence、…/decisions 哪些证据可查，哪些事项需要人的决定？ G2/G3
公司 …/settings 组织、授权、模型绑定、数据保留与兼容性？ G1 基础，G4 完善

路由是产品页，不自动等于同名 API。子页面通过嵌套导航/Tabs 收纳，公司侧栏保持约八个一级条目；“待决事项”可置于证据分组及页头入口，计数是需要实际处理的责任，不是全部未读消息。

首版不提供办公室入口、不显示“即将上线”的空场景，不用一个只会显示 loading 的页面伪装功能已经接好。尚未实施的非核心页隐藏或显式列为不可用；不能填入假数据伪装真实公司。

38.2 公司总览：先让人做决定，再提供钻取

建议结构（文本线框，不是运行截图）：

公司切换 / 公司名称                         连接状态 · 数据截止时间
当前使命：目标简述                       [查看使命] [暂停新派发]

[最近有效进展]        [需要决策]          [资源占用与剩余口径]

当前里程碑与阻塞                        待决事项 / 未知在途动作
 ├─ 已验证的阶段                         ├─ 按风险、期限排序
 ├─ 正在推进的阶段                       └─ 每项可追到证据
 └─ 下一步、依赖、负责人

团队运行摘要                            重要活动（有限条数）
工作 / 休眠 / 等待 / 接班                变更 → 谁受影响 → 结果

卡片数字来自明确查询；不超过少量真正帮助决策的摘要。总览不展示“公司完成 83%”之类无法解释的进度。可以显示“本期 3/5 个里程碑已按规则验收”，并附 PlanRevision；任务重新拆分后解释分母变化。经营结果与任务完成分开。

待决事项优先级由后端规则给出，界面不通过模型另算一套。没有需要人处理的事，就显示“暂无需要你决定的事项”，不是制造通知保持活跃。

38.3 员工页：像档案与工作记录，不像会话集合

默认员工名单使用适度密度的表格或列表：工号/岗位、当前模型、当前任务、主要等待原因、责任数量、用量口径和最近观测。点击进入员工详情，Tabs 包含概览、任务与责任、协作消息、记忆与决策、模型与接班、授权工具。未获授权的栏目不返回其内容。

稳定 URL 以 EmployeeId 定位，Session/Attempt 是历史记录下钻项。更换模型后，不新增一张“新员工卡片”，不把旧模型会话留作一个还在占岗的假员工。

员工详情可以显示两个并存事实，例如“付费推理已休眠 / 后台测试仍运行”。lost_contact 与 sleeping 必须明确区别，最后可见状态过期时显示“最后观测为…，当前未确认”。

公司已有固定岗位而某岗位没有合格模型时，显示“未配置合格执行后端”，允许查看和修改配置；不自动创建另一位员工绕开问题。

38.4 任务、证据和协作的关系

任务详情围绕输入合同、负责人、依赖、候选产物、审查 finding、验收和 Action 回执组织。任务看板是查询投影；若允许拖动，只能提议合法状态/优先级变更，不能从“执行中”拖到“已验收”来改变事实。首版用按钮/菜单完成变更即可，不把拖拽作为必要功能。

协作时间线把 Message、Obligation 和系统接受的事实区分显示。一个“收到”不关闭责任；一个模型的发现不自动变成系统批准。重要条目可跳到原消息、对应任务、依赖版本和解决证据，不默认展开所有 token 日志。

证据页保留 passed / failed / inconclusive / not_run / invalidated 的区别。已过期的通过记录仍作为历史存在，但不放在当前绿色通过汇总中。

38.5 资源页：经济意义比总 token 更重要

展示 Group/Company/Mission/Employee 维度，但同一消费只记一次，不能把父子汇总再相加。金额由后端给出固定精度字符串、单位与截止时间；多币种不无汇率证据地合并。真实消费、估算消费、在途预留、未知责任、保护收尾额度分别说明，不把它们都叫“已花”。

订阅额度与 API 计费单列；无法取得精确余额时显示“当前不可得”或“估算”，不画伪精确仪表。存储同时包含工作区、构建缓存、日志/证据、数据库/WAL 和备份；清理操作展示会删什么及保留 pin，不默认选择唯一恢复依据。

38.6 全局导航不是业务权限

“看得到入口”不是授权；服务端仍校验所有查询、导出和动作。页面无权限时不显示其他公司的名称、余额或任务摘要作为错误提示。搜索默认当前公司；集团搜索仅返回当前人真实有权访问的范围，并标明所属公司。

可以先提供普通筛选和搜索栏，不强制首版做复杂命令面板。后续命令面板也只是对现有动作的入口，不获得更高权限。

38.7 QQ 通知是设置与待决事项的一部分

在既有设置页面增加接管通知配置；待决事项显示事件 ID、需要人的动作、投递状态及失败。没有 QQ 群聊控制面或另一套公司数据。界面只在明确测试操作时外发样本；通知目标变更要确认披露范围。见第 42.7 节。

38.8 沿现有导航增加能力页签

集团设置收纳公共 Skills/MCP 定义，公司设置收纳版本固定的能力绑定；员工详情新增“工作环境与工具”。任务/证据/接班页关联已用版本和调用回执，不新增插件市场或办公室。集团候选信息不自动暴露给无权公司；MCP 返回资源以相同访问与安全渲染规则展示。见第 44.8 节。

38.9 资料、工作指导、作业和交付入口

使命详情增加资料/指导/交付Tabs；任务详情增加Job日志、服务就绪和目标应用验证；公司反馈待办标来源和coverage。展示输入stored/usable、Guidance received/applied、交付ready/用户接受与终态backlog区别。只通过已认证隔离预览查看生成应用，不在工作台同源执行。

39. 关键交互流程：人工建编制，日常工作自治

39.1 建公司向导：创建与启动分开

创建过程由人配置固定团队。允许选择预定义模板、手动修改草案；首版不提供“让 AI 自动组建并开始工作”的隐藏路径。模板不是权限授予，组织结构也不是从进程列表中自动反推。

用户决定组 需要确认什么 模板/运行时承担什么
1. 目标与资料 公司名称、业务目标、项目/资料、允许的探索范围 保存草案；可以未有完整规格，不启动模型
2. 固定团队与模型 人选定模板、岗位和默认/预批准替补 显示覆盖缺口/独立审查路径；不自动招聘；不要求理解内部epoch
3. 工作环境与工具 参考环境、Skill/MCP选择、数据目的地与实际资源 基础/目标环境区分；高级技术参数由模板承载；探测需明确授权
4. 资源与边界 费用单位/保证等级、预算、收尾保护额、期限及外部动作 用人可懂的摘要展示全部有效权限；不藏风险，不默认全选
5. 审阅与创建 当前草案版本、仍需人介入的类型、可执行与未验证部分 持久创建，保持未启动；高级字段仍可展开
独立启动 明确启动指定MissionRevision或有界探索 当前条件重新验证；不依赖前端自报，不要求项目依赖已全部ready才能规划

“保存草案”“创建公司”“启动使命”采用不同按钮和命令回执。中途退出可恢复服务端草案；没有保存的部分明确提示，不把敏感完整表单静默放 localStorage。缺少合格后端可以创建草案，但不能进入真实执行。

资格检查分“已有报告/被动可达性”“真实模型探测”。任何会调用付费模型的检查必须显示预计范围并受预算授权；不能用户点了一次下拉框就烧一次模型。

39.2 组织修订与人员固定性的交互

固定不等于数据库永远不可修改。人可以在允许的安全边界修订员工名称、模型绑定或岗位配置；涉及职责/权限/审查关系的变更先展示差异、受影响任务与版本，再按第 30、32、35 章执行。不能用同事聊天触发同等组织变更。

首版不提供直接删除正在承担任务或未闭合责任的员工。手动移除/重新分配若尚未实现，界面明确只支持排空/停用，不用删除档案清掉问题。模型会话结束不自动停用 Employee，启用一个新 Session 也不自动新增岗位。

39.3 换模型：配置变了和新模型正在工作是两件事

界面分别显示目标绑定、当前活动绑定及接班阶段。休眠员工切换配置后可显示“新绑定已保存，下次真实工作时使用”；不得为了让进度条跑完而启动付费推理。活动员工的接班卡片展示 draining、reconciling、isolated、restoring、validating、active 等后端状态与证据。

前端不能把下拉框的值先改成新模型，然后显示“切换成功”。遇到旧写者未停止、目标资格不足或资料流转不允许时，保留工号和责任，显示可操作的阻塞原因。

39.4 暂停、急停、撤权与危险动作

“暂停新派发”不代表取消既有动作；“请求中断”不代表进程已停止；“紧急隔离”需要隔离证据；“撤销授权”需要屏障状态。这些文案遵循后端契约，不能用一个通用“停止成功”代替。

范围明确、可逆的普通暂停可一次操作提交并展示回执，不强迫用户每次填确认短语。扩权限、增预算、删除证据、发布至外部等高影响动作必须确认公司、对象、变化前后、在途影响和当前版本。紧急隔离入口始终容易找到，但不绕过身份验证，也不等待模型审批。

浏览器看到的数据过期时，增权限/增加支出/发布等操作先获取当前状态并重新确认。减少风险的暂停/急停不应仅因业务详情 stale 就被 UI 隐藏或禁用：仍可向可达且经过认证的控制端请求，状态由实际回执确认。控制端不可达时显示“请求未确认”，不排入离线队列等待将来突然执行。

39.5 异步命令、冲突与未知结果

提交后返回 operation_id，UI 显示“已受理”及具体阶段，不做成功乐观更新。临时网络超时不等于命令失败：用原 request_id 查询回执；不能用户点“重试”就换一个幂等键再次创建公司、发布或扣费。

遇到 expected_revision 冲突，保留用户草案，展示当前版本和差异，让人重新确认；不能自动用旧草案覆盖新政策。公司切换或对象变更时，未提交的确认弹窗取消；已提交操作保留其原公司归属，结果不能弹成新公司的成功提示。

未来即使加入批量操作，也必须逐对象返回结果。首版高风险动作不提供跨公司批量批准；通知弹窗不作为唯一审计记录。

39.6 记忆更正、审查与责任闭合

记忆纠错入口提交 CorrectionRequest、来源和理由；不允许像普通笔记一样覆盖原文并悄悄消除引用。影响关系与“需重新核查”状态可查看，活动模型已加载的错误背景要按既定恢复规则处理。

审查决定显示产物版本、输入合同、实际检查、未解决 finding 和批准者。待审内容发生变化时阻止复用旧确认。解除阻塞需要规则允许的证据或明确例外决定，不能前端把 finding 行删除就过关。

个人待决事项与员工 Obligation 分开：前者是人必须处理的决定，后者是员工对同事/任务的承诺。阅读一个条目可以清除“未读”，不能自动把未履行责任标记完成。

39.7 通知测试、接管确认与正式审批

QQ 草案保存、测试发送、资格通过、启用通知分别反馈。测试也是真实外发，需要人确认目标与内容；阅读或刷新不发送。确认接管只清除同级提醒，不恢复使命、不增加预算；批准和恢复沿现有管理命令执行。无手机可达的安全入口时显示 incident ID，不制造免登录执行链接。详见第 42.7 节。

39.8 建公司时批量绑定资料和工具

执行后端与授权步骤增加工作根、共享资料、Skills/MCP 选择与每岗权限预览。保存和创建不扫描任意目录、不运行脚本、不连接服务；读取已批准目录与资格报告是无模型查询。显式扫描有边界，连接探测提示本地程序或外部访问，单独确认后执行。模板升级不自动扩大已运行员工的能力。

39.9 人的正常工作交互

资料上传绑定、指导/澄清、正式变更、人工接管/补丁交还、下载/反馈，按第45章串联。上传或阅读不自动付费；人写工作副本前要取得真实交接回执；补丁核对和失效重验完成后再恢复。

39.10 简单界面不等于含糊执行

普通建公司流程以五组决定承载，复杂配置由明确版本模板和高级面板消化；真实账户/出口/费用/任务范围不可隐藏。指导入口区分下一边界和先暂停再处理；后者使用关联hold的管理命令，显示在途情况和屏障，而不是等模型理解一句“先别做”。产品验收记录首次使用时间和误拦，见46.5/46.8/46.11。

40. C-WORKBENCH：前端状态、命令与可信展示契约

40.1 可观察，不制造第二套运行时

浏览器不调度 Agent，不持有模型/平台密钥，不直连 PostgreSQL，不读取宿主工作目录，不执行发布，不从供应商会话中自动生成 Employee。所有视图从同一控制 API 读取，所有管理动作经过同一命令与授权入口。

浏览器关闭不会停止公司；组件卸载不取消已接受的业务任务；浏览器定时刷新不调用模型。查看员工、悬停卡片、筛选日志、切换主题不会唤醒员工。需要模型参与的额外总结另建显式有预算的任务，不隐藏在普通 GET 查询后。

40.2 多维状态，不用一个 online 布尔值解释一切

维度 示例 展示要求
持久身份 employee_id / role_revision 长期稳定，绑定业务身份而非 session
调度 sleeping / wake_pending / paused / waiting_quota 说明是否有可执行工作与准入障碍
执行 active_requests、工具在途数、当前 Attempt 有后台工具不等于正在推理
工作 当前任务、候选、验证、等待依赖 进程活动不代表业务进展
数据新鲜度 observed_at / received_at / stale_after “最后观测”不伪装成实时确认
来源模式 real / simulated / unavailable 模拟页面始终显式标识，不混入真实指标
费用质量 reported / estimated / unavailable unavailable 显示未知，不变成 0

页面可以从这些维度选一个主要状态标签，但不能丢掉重要并存事实。例如“休眠，另有 1 个后台测试在途”是合法显示；不应把该测试强行转换为付费推理活跃。后端枚举或 schema 无法识别时，显示不兼容并限制受影响命令，不能默认映射到 working 或 success。

40.3 ViewModel 与版本边界

建议读取响应具有 ViewMeta：schema_version、company_id、entity_revision、snapshot_cursor、observed_at、data_mode 和能力/权限摘要。必要的大整数用十进制字符串；不同对象、公司或恢复代际的 revision/cursor 不能直接比较。

ui/status-catalog.json 与 examples/workbench_employee.example.json 是中立设计样本，不是当前服务器已经返回的 JSON。具体 OpenAPI 实施时从唯一 schema 生成类型，不能三个页面各写不同字段解释。已删/无权访问资源不返回敏感元数据来“帮助定位”。

40.4 查询缓存与公司切换

TanStack Query 按 query key 区分缓存，因此所有改变查询数据范围的变量都应参与 key；这也是其官方文档强调的规则。U04 本项目建议 key 包含认证会话的非秘密标识、company_id、资源类型/ID、筛选和视图版本。不能只用 ['employees'] 缓存所有公司。

切换公司时关闭旧视图订阅、取消或隔离旧请求，晚到响应仍只归其原 scope；不允许旧请求回调写入新公司的状态。跨公司切换不使用上一家公司列表作为 placeholder。撤销权限或退出登录后清空相关缓存、关闭详情与原始日志；后端仍逐请求鉴权。

缓存默认内存存在，不把公司原文、消息、API 响应整体写入 localStorage/IndexedDB。主题、列宽等非敏感偏好可以本地保存。没有离线管理命令队列，没有 Service Worker 离线重放批准和发布。

40.5 SSE 与查询快照的衔接

单个工作台会话使用集中 EventStreamClient，不为每张员工卡单开 SSE；按当前授权和作用域过滤。初次读取带安全水位的权威快照，再从该水位订阅增量；保留窗口不足则重新取快照。第 19 章的公司级提交有序游标仍为底层规则，前端不以自己见过的最大 UUID/时间戳代替。

事件用于使相应查询失效或更新带版本的小记录；重复和晚到事件不倒退已确认状态。失效/撤权信号优先处理，普通活动更新可小批合并。用户滚动查看旧日志时不强行跳到底；展示“有新活动”入口。

SSE 是服务端到客户端的单向流，命令仍走 HTTP；原生 EventSource 会自动重连，但不提供本项目的持久补漏语义。HTTP/1 下同域多连接存在浏览器限制，因此不能每个组件各建一个流。U05 服务端设置正确缓存/缓冲策略并校验监听权限；跨多个标签的连接数有界，耗尽时明确退化到有限只读轮询，不改 WebSocket 架构来掩盖订阅泄漏。

断流显示 reconnecting/stale，不把旧值清零。认证失效停止受保护数据流；权限变更需使相关视图失效并刷新可见范围。游标过期、服务器恢复代际变化、协议升级都要重新获取快照，不能拼接两个不兼容事件流。

40.6 命令客户端与安全语义

同源 HTTP API 与既定管理认证配合。采用 HttpOnly/SameSite 会话凭据及 CSRF/Origin 校验；生产 TLS 下要求 Secure，loopback 开发策略单独记录，不能把开发宽松配置外推到远程访问。浏览器没有通用 Agent 管理员 API token、没有数据库口令，也不把 secrets 放 URL、localStorage、SSE 参数或日志。

CommandClient 保存非秘密的 request_id/operation_id 和明确的原 scope，用以追踪未知回执；高风险写请求默认不做自动重新发送。自动 GET 读取可有限重试，但控制端失败、版本冲突和写结果未知不能被通用重试器无限重放。应区分前端查询网络消耗和实际模型费用。

所有关键动作只在后端回执或后续权威查询确认后改变实际完成状态。客户端 can_execute/按钮禁用只是体验提示，不是权限保证。多标签同时提交时后端的版本与幂等规则必须仍然有效；UI 的 loading 按钮不能代替它们。

40.7 不可信内容不能通过工作台获得执行能力

模型文字、仓库文档、日志、来源链接和产物预览均是不可信内容。默认禁用原始 HTML；禁止直接注入 SVG/脚本、javascript 链接、任意 iframe 和终端控制序列。需要 Markdown 时只使用受限渲染与链接协议白名单；图片/外部资源不自动加载，避免来源跟踪及越过既定数据出口。

报告和导出要经过同等授权与脱敏规则；敏感路径、凭据和完整提示词不进入前端遥测。未使用第三方分析服务时，不为“改进体验”加入跨域上报。浏览器安全策略必须和实际构建配置一起验证，不以一个 CSP 标题代替完整输入处理。

40.8 只读视图的未来扩展边界

未来办公室、组织图或其他外观从同一 ViewModel 读取，可复用现有详情和命令入口；它们不拥有队列、记忆、预算或权限。第一版不创建通用场景 SDK，不新增员工坐标/移动数据库，也不保留隐形后台 3D 渲染循环。

后续画风即使完全推翻，Employee/Mission/Task/Action ID 和这套 API 仍保持工作语义。动画只响应已确认事件或本地装饰逻辑，不生成业务事件，不调用模型制造“同事在聊天”的表演。

关联：REQ-01/06/07/12/13/14/19/20/21/22；FT-23/31/32/34/38/46/51/55；UI-01～24。

40.9 通知与快照的额外映射

工作台快照数据和安全水位来自同一短数据库快照。QQ 投递的 provider_accepted 不显示成“已读”；通知资格、持久问题与管理决定分别呈现。route 撤销后晚到响应仍按原版本归档，不重新启用通道。QQ 不承担浏览器身份认证，也不触发离线危险命令重放。

40.10 能力状态与命令遵守同一可信展示契约

分开展示配置 draft/approved、连接状态、实际可用工具、资格及费用可见度。访问目录/详情不调用模型，也不隐式运行 MCP 探测。服务描述/图标/资源都是不可信数据；变更绑定、启用、探测、撤销用同一作用域/expected_revision/操作回执机制。跨公司缓存与原文导出沿既有隔离规则，UI-33～40 为对应计划。

40.11 输入与交付的安全展示

上传storing/processing/partial、环境与Job阶段、BrowserRun证据、Guidance采用、Delivery和Feedback覆盖分别展示。管理API只处理命令/记录；浏览器不持GitHub/测试账号密钥；生成应用在独立信任域，不能靠只换端口或iframe自动安全。

41. 前端交付、无障碍与视觉验收

41.1 首版要做到什么，不需要做什么

首版交付专业工作台，而非孤立的漂亮静态首页。公司创建、固定员工、任务/责任查看、接班与暂停回执、资源口径、证据和异常应形成真实的纵向路径。没有后端能力的页面可在隔离 preview 模式用 fixture 演示，但默认 runtime 模式不能接失败后悄悄 fallback 到 mock。

先做公司总览、员工详情、任务/验收详情三个代表性页面，在浅色/深色、正常/等待/未知/失败状态下审阅布局，再铺开其他页面。审美验收由维护者看实际页面决定；自动截图没有能力证明“审美高级”。后续调整 token 和布局可以持续进行，不更改运行时权责。

不在首版交付：办公室、角色动画、游戏音效、自动生成人设头像、地图编辑、全屏 3D、实时协同富文本编辑器、任意业务 BI 拖拽、复杂主题商店。

41.2 响应式与无障碍目标

以 WCAG 2.2 AA 为目标，不因使用某个组件库就宣称达标。普通文字与背景至少 4.5:1，符合大字定义的文字至少 3:1；必要控件边界/状态图形按非文本对比规则检查。状态同时包含可读文字；焦点可见且不被固定页头遮挡。W3C 也要求可访问的操作不只依赖拖拽，并对目标尺寸和 reflow 给出规则。U06

工作台常用点击区域默认 36–40px，高风险或触屏主要操作优先 44px；这是本项目的舒适性目标，不把 44px 误写成全部 WCAG AA 项的唯一门槛。320 CSS px 宽度下正文和基本操作可重排，复杂表格/代码采用有标签的局部横向滚动；页面本身不整体溢出。200% 文字放大不丢失关键操作。

对话框支持键盘进入、可见标签、合理初始焦点、Escape/取消与关闭后焦点返回；重要内容不是只放在 hover tooltip。焦点规则以 WAI-ARIA 对话框模式为依据，再对实际页面测试。U07 表单错误贴近字段并有汇总，不靠 toast 闪一下；背景事件不反复抢走正在输入的焦点。

界面文本默认中文；状态键、ID 与翻译文案分离，预留英语长字符串的版面空间。时间有明确时区，金额有币种，ID 可复制。数字、版本和单位不在翻译时改变含义。

本地交互 指定参考机上常用操作无明显卡顿；目标反馈在约 100ms 内 排除后端/模型时延，记录测量环境，不包装成普遍性能保证
动态更新 普通事件可约 100–250ms 合并；关键撤权/异常不人为拖延 测视图延迟、流式更新与焦点稳定
页面尺寸 1440/1280/1024、768、390/360/320 宽度；深浅主题 浏览器截图与交互检查，复杂表格局部滚动

以上数值是提出的预算和测试 fixture，不是完成成绩。测量后可通过 ADR 调整。选择 Go 不改变浏览器 bundle；选择现代前端也不允许为了图表/办公室膨胀首屏依赖。

41.4 前端测试与阶段

继续使用 Playwright 验证真实 UI 流程；组件/纯状态转换可使用 Vitest，类型校验必须独立运行，不能将 Vite 构建成功当作 TS 类型全部通过。U10 可以用 axe 辅助无障碍扫描，但自动扫描不能替代键盘与人工检查。U08

UI-01～24 是新增测试计划，与 FT-01～56 的后端/故障测试分开记录。截图、token 对比、fixture 校验、mock UI、真实 PG+API+UI、真实 Agent 的结果分别报告。没有真实产品前端时，只能记录文档排版检查和静态一致性。

阶段 UI 交付 验收重点
G1 AppShell、统一 token/组件、建公司草案、总览、员工与任务基础页 人工建编制；不自动开始付费；空/失败/权限状态；公司切换
G2 接班详情、协作责任、休眠与连接状态、操作回执 新模型不换员工；休眠无 GET 副作用；202 不当成功

UI 不增加另一套后端，也不要求延后持久性/安全实验。视觉完善可以和核心验证并行，但不能用漂亮 mock 替代真实能力。

41.5 给后续前端 Agent 的明确约束

从 ui/FRONTEND_SPEC.md、tokens、状态样本和页面地图开始实现；共享组件先行，不各做一套 dashboard。所有修改走现有 Go API，不导入 Paperclip 的后端/adapter workspace 包。不要以“企业风”生成满屏蓝色按钮，也不要重新引入已延期的办公室。

交付同时给出正常、休眠、等待、未知、无权限、连接中断、版本冲突与模拟模式的样本截图。报告哪些交互经过真实后端，哪些只是 fixture。对视觉参照的借鉴，不等于使用其品牌素材或原实现；直接复用代码/图标时另行记录来源与适用许可。

本版前端准则：像管理一支真实团队，而不是观看员工上班表演；界面可以克制，事实和风险必须清楚。

41.6 通知 UI 的补充验收

UI-25～28 检查测试外发确认、平台接受/未知与接管确认分离、目标披露/安全链接，以及禁用路线后的待发取消。仍区分离线文档阅读器和真实产品页面；没有接 QQ 就不写“推送成功”。

41.7 本轮能力 UI 交付

前端增加公共库/能力绑定/员工工具页签与调用明细；沿现有 token 与组件，不引入第三方 MCP UI 运行器。UI-33～40 测试创建不执行、跨公司目录、连接资格、版本冲突、接班和不可信资源。产品页面未实现时仅允许明确模拟预览，不能借本章样本显示真实连接成功。

41.8 正常工作UI验收

UI-41～48对应输入、环境/作业、目标应用证据、人机指导/交还、交付下载与反馈。静态阅读版排版通过不等于这些页面已实现，更不等于浏览器真正验证了员工生成的应用。
