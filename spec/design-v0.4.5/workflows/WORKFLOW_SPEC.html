45. 正常工作闭环：资料进入、环境准备、开发调试、指导、交付与反馈

45.1 本轮定位与最小可用路径

本章补齐的是“允许员工干活时，怎样真正把事情干成”。 不增加岗位，不换控制面技术栈，不以表单审批取代员工自主工作；将已有 Task、Artifact、Evidence、Action、Obligation、CapabilityBinding 和预算机制串成可用流程。七份合同是模块边界与用户体验约束，不是七个微服务。

人提交目标 + 原有项目 + 参考图/文档/测试数据
  → 原件安全接收，内容表示与输入版本就绪
  → 固定规划岗规划，环境准备工作按预授权执行
  → 员工编辑代码、运行命令，启动受管理测试服务
  → 受控浏览器实际操作应用并保存证据
  → 人补充资料/纠偏，必要时安全接管并交还
  → 交付固定版本、运行说明、验证结果与下载入口
  → 在有效维护使命中接收新问题；否则进入公司待办池

“入口存在”“实现完成”“对支持组合测试通过”仍为三个状态。本章描述完整工作链与失败行为，R1只要求46.3所列最小可用子集；PDF/CSV/ZIP、真实反馈等按R2资格开放，不能用全链蓝图阻塞最早价值实验。精准版本/账号/执行物/费用在资格测试后填写；样本execution_enabled=false，没有访问用户工单。

最小能力 首版参考实现路线 不宣称已经覆盖
资料入口 工作台上传 + 受信 CLI 导入宿主目录/仓库；统一 Artifact 接收服务 所有办公格式、无限大小、任意扫描件均可理解
项目环境 一个 Linux Node/npm 锁文件项目 profile；工具环境与控制面分离 任意语言、GPU/移动端构建、任意 Dev Container 配置自动执行
命令与服务 既有 supervisor/合格 harness 映射为 JobRun；程序管理状态 浏览器内完整 Web Terminal、通用远程桌面
浏览器验证 隔离 Playwright/Chromium 执行环境，固定访问范围 任意登录站点、验证码、绕开访问限制
人类协作 工作台上下文指导、结构化变更、受控补丁导入/交还 QQ 远程命令、多人实时编辑同一工作树
交付 不可变 DeliveryManifest + 鉴权下载/说明/证据；预览可选 必然发布生产、构建件适配所有 OS
外部反馈 已授权仓库的 GitHub Issues 只读轮询；界面手动反馈是无外网入口 默认接入用户所有仓库、工单评论/关单等远端写操作

GitHub 是本版第一个真实反馈来源的设计选择，不是已经绑定用户账户。搜索由获授权的搜索 MCP 提供；没有搜索服务时仍可读明确批准的 URL，但不得称为已完成开放网络搜索。

45.2 C-INTAKE：资料接收与模型可用表示

45.2.1 三种入口，四个不同完成状态

入口为浏览器选择文件上传、受信 CLI 导入控制宿主目录、登记获授权仓库/URL 后显式执行抓取。浏览器中的电脑路径不等于服务器路径；远端管理页面不提供任意宿主路径枚举。用户原目录默认只读取样、复制到受控快照，禁止在“导入”时覆盖原项目或改写其 Git 状态。

过程分为 uploading → stored → processing → usable / partial / unsupported / rejected；“stored”只表示原件完整保存，不代表文档已经解析、更不代表模型已读取。每个文件保留原始名称作为显示字段，存储使用受控 ID；关联公司、使命/任务、来源、字节数、内容 hash、敏感等级和保留政策。

上传完成请求幂等，最终 hash/大小由服务端确认；中断重传不能生成重复输入绑定或触发重复任务。首版不强制实现分片续传，超限应在上传前提示，服务端仍执行硬限；部分上传超时回收，尚未固定的文件不能供员工读取。URL 获取使用现有数据出口/SSRF 规则，网络接收不在数据库事务内进行。

上传只接收资料，不启动使命、不安装依赖、不自动接入其中的 Skill/MCP。 用户明确将资料加入一个已运行任务时，才创建 InputRevision 和相关信号。确定性解析可沿预授权的处理配置运行；需要付费视觉、转录或额外外发的转换必须先通过对应授权及预算，普通上传按钮不隐藏一次模型调用。

45.2.2 支持矩阵及可定位表示

类型 已开放该类型时的必需路径（R1/R2见46.3） 保留的定位与限制
UTF-8 文本、代码、Markdown 有界读取/搜索；换编码需显式报告 原件 hash、行范围、截断与读取版本；不静默替换乱码
PNG/JPEG 截图 图片表示，经已验证的 harness 图片输入送给模型 像素尺寸、变换记录和原图引用；路径文本不当作已看图
PDF 文本提取 + 按页栅格表示；图表/版式任务可取对应页面 原页码、解析器版本、字符/页面覆盖率；扫描或加密无可用路径则 partial/unsupported
CSV 表头、行数/列数、有界分段读取；类型为推断且可纠正 分隔符、编码、行范围与原始字段；不执行公式或自动当代码
ZIP 项目包 检查清单后解包至新隔离根 原包和树清单指纹；不自动运行安装钩子、仓库配置或嵌套压缩包
Git 仓库 获授权的只读获取 + 固定 commit 的受控副本 仓库身份/commit/ref；未提交本地改动通过明确快照另存
其他格式 保存后明确不可处理，或拒绝不支持类型 不用“已上传”掩盖 xlsx/docx/音视频/超大资料尚不支持

PDF 文本与页面图引用应可互相定位；不要求 OCR 首发，但不能将扫描页没有提取文字误认成空页。若任务确需扫描页内容，使用获授权的视觉路径或明确等待转换。CSV 导出到电子表格时另检查公式注入风险，原始数据保留不变，显示层不擅自改值。

输入原件、DerivedRepresentation 和实际 ModelInputManifest 分离：记录本次会话实际收到的文本范围、图片/页面、转换摘要和省略项，而非只保存“这个文件存在”。目标模型与 harness 的组合必须支持该输入类型；替换模型时重新按需求核对，不能将图片悄悄变成文件名、将无内容的链接当作已经提供信息。

45.2.3 处理环境、安全和共享

限制单文件大小、文件数、解压后总大小、嵌套深度、页面/像素上限、解析时长与内存；实际限值在部署配置锁定。文件扩展名、浏览器 MIME 和 magic 都不是单独的安全证明，解析器运行在无业务凭据、默认无外网的隔离工作进程。输入不放在工作台可执行 webroot；受控下载和预览分别处理。W01

ZIP 拒绝路径逃逸、绝对路径、重复条目覆盖、链接/特殊文件及大小声明不符；按解压实际字节计量。原件不因解析失败消失。仓库导入不继承宿主 HOME、credential helper、任意 filter/hook；submodule/LFS/额外 URL 需在来源策略内，缺失内容明确展示，不按半个 checkout 宣称完整。

解析产物通过既有 staging→ready/pin/GC 协议发布。管理员选择哪些输入绑定到任务；同公司获权成员自行读取，无需主管转发。替换附件生成新 revision，明确哪些任务需要重读；已有模型上下文不会自动忘记旧图，按 C-MEMORY 和 C-GUIDANCE 处理。

**接受标准：**员工能指出所依据的文件及范围；图片路径确实被转成可用图片输入；失败和不支持有明确 UI；越权或半成品不会被当作已经读懂的资料。

45.3 C-ENVIRONMENT：正常依赖准备不是隐形插件安装

45.3.1 控制软件的栈与目标项目的栈分离

控制面继续用 Go/PostgreSQL，工作台用 React。员工开发的项目可以采用不同语言；首版只认证一个明确的 Node/npm 项目 profile，其余语言在同一环境接口下逐项扩展，不因为仓库写了 Python/Java/Rust 就自动拥有相应运行能力。

ProjectEnvironmentRevision 保存：工具链/镜像指纹、代码输入 revision、lockfile 指纹、依赖来源、安装步骤/脚本政策、构建/测试/启动入口、必要服务与健康条件、工作根与 scratch、网络出口、资源上限、缓存边界与资格记录。项目内 README、package.json、devcontainer.json 可提出候选配置，但不自动成为可信部署脚本。

人可以一次批准项目环境政策；授权内重复安装、构建和重建无需逐次审批。environment.ensure 查询已有准备结果，必要时创建独立 EnvironmentPreparationRun；必须先准入再执行，多个员工同时请求同一准备键不会并行破坏同一依赖目录。共同可复用的是已固定的只读环境层，各员工的可写工作目录独立。

45.3.2 明确允许的依赖操作

首版禁止的是未授权的安装、宿主全局修改，以及发现/加载 Skill 或 MCP 时偷偷安装。不是禁止在隔离项目环境中，按批准政策自动准备依赖。 第 44 章的自动安装范围以此限定。

Node 参考 profile 使用已确认 lockfile 的 clean install。npm ci 要求锁文件、会因清单不匹配而失败且不会替用户更新锁文件；它仍要单独处理安装脚本。ignore-scripts 不意味着之后显式 npm run 也不执行代码。W02

参考安装按固定 npm 版本执行 npm ci --ignore-scripts --no-audit --no-fund，但这只是一个可审核步骤，不是万能沙箱。需要生命周期脚本的项目应通过明确的 install-script policy，限定解析到的包版本、网络和资源后执行；不能遇到失败就自动改成允许全部脚本。不同 npm 版本的脚本策略能力以资格测试为准，不凭某个新 flag 假定所有环境已支持。

lockfile 中的 tarball/git/file/registry 目标、项目 .npmrc、额外下载及工具遥测都是网络/文件输入，受批准来源和最小 env 限制。不要把广域 registry 凭据留给后续任意测试；支持凭据访问的准备阶段与无凭据执行阶段分开，或将必要短期凭据与该受信工具范围绑定。安装内容仍是不可信代码。

开发中确需新增依赖，可在预授权的来源、许可类别、脚本/体积/网络边界内提出并接受 DependencyChange，生成新 lockfile 和环境 revision；越过边界才找人。不得“每加一行 import 就审批”，也不得无声扩大宿主/平台权限。无锁文件或其他语言缺合格 profile 时，返回 environment_plan_required 并交固定规划/开发岗提出方案。

45.3.3 附属服务和环境状态

测试数据库、缓存、模拟 API 使用独立 ToolService/临时卷和最小测试凭据；禁止将组织控制数据库当作被测应用的业务库。参考 Node demo 可以先不需要外部数据库；使用数据库项目的资格测试另包含初始化、迁移、清理和数据隔离。

环境状态为 unprepared / preparing / ready / failed / dirty / revoked，由准备回执和健康检查决定，不由模型自报 ready。准备失败保留原因与有界输出，不反复触发所有员工安装。源代码、lockfile、镜像、政策或工具链变化后，按受影响依赖失效；不把任意旧 node_modules 当验证基线。

生产/审查缓存按信任级别隔离，已变更可写缓存不作为独立验收唯一依据。环境资源计入公司/使命预算，长作业和数据库临时数据纳入回收；保留正在被任务、接班或交付引用的必要层。EnvironmentReady 是一个可核验依赖，可以唤醒等待任务；普通检查由程序完成，不烧模型轮询。

45.4 C-JOBS：命令、长作业与开发服务

45.4.1 一份执行身份，不造第二个 Shell 运行时

普通本地开发允许在 Task/Attempt 的受限环境内运行合格命令。JobRun 统一包装已认证 harness 原生命令或 supervisor 执行；同一次真实执行只有一个 JobRun，不将原生工具事件与外围脚本记成两次独立执行。scripts.run 是固定 Skill 入口的专用路径，不等于员工只能运行提前写好的技能脚本。

命令记录 cwd/workspace、argv 或显式 shell 脚本文本的 hash、工具环境 revision、env 白名单、输入策略、所用授权、超时/输出/资源限制，以及 company/employee/task/attempt/incarnation/epoch。执行自由度由实际沙箱约束；不能只靠字符串禁词宣称 Shell 安全。共享分支更新、真实发布和外部账号写入仍必须走 Action，不能藏在普通命令后面。

Job 种类 生命周期目标 完成/异常判定
batch 构建、测试、有限数据处理 退出码/结果文件与证据齐备；0 只表示进程正常结束，不等于任务验收
service 前端 dev server、后端 API、测试 DB 独立 startup timeout、就绪探测、有限驻留寿命；持续运行不是命令超时
controlled_input 明确获准的有限交互程序 有 typed prompt 与输入渠道；默认 stdin 关闭，不无期限等人

首版不提供通用 Web Terminal。遇到未支持的登录/密码/确认交互时报告 input_required，只通过受信身份流程处理，不将密钥写进普通聊天。测试脚本需要 TTY 且未获资格时明确 unsupported，而不是让 Agent 反复空等。

45.4.2 状态、日志与暂停

accepted → starting → running，service 另记录 readiness=not_ready / ready / unhealthy；结束为 exited/failed/cancelled，无法核对保留 outcome_unknown。取消 ACK 不等于进程树和远端工作已经停止。日志有 offset、truncated/gap、大小限额和来源；长输出落有界文件引用，不把所有 stdout 注入模型或控制 DB。

员工可用 jobs.start/status/logs/stop；状态和日志查询不额外调用模型。jobs.start 带幂等键，回执丢失先核对现有 JobRun。普通工作等到服务/测试事件时休眠；JobRun 的运行时长、工具费用与资源不因模型休眠而清零。全局急停路径不被日志洪峰或满员作业阻塞。

45.4.3 服务地址、借用与真实就绪

服务只能绑定其隔离网络内的允许地址/端口。记录 ServiceEndpoint 与服务实例 generation，不能按“3000 端口有人回应”就认定是当前项目；ready 探测必须同时验证所属进程/容器、预期代码 revision 和配置的健康响应。禁止自动 reuse 不明来源服务。Playwright 已提供命令、ready URL、多服务及关闭配置；本项目需要在其外保证资源身份和版本正确。W03

前端/测试员工经已批准的 peer access 借用服务，得到对特定服务端口的访问授权，不获得所有者文件写权、宿主网络或 DB 权限。记录消费者和 TTL；有获授权消费者时不会仅因原员工睡眠立即关闭，无消费者且到 idle deadline 后由程序回收。明确关闭/撤权优先于普通借用；调用者得到清晰失效状态，不转发到刚被复用的新端口。

开发模式可以带热更新，但记录 mutable=true，不能用它的截图为不可变 candidate 最终验收。验收服务从冻结产物/干净快照启动，截图和结果绑定该 service generation。

45.4.4 换班、重启与回收

长期服务由 supervisor 管理，而非依赖模型连接维持。换脑时核对旧作业：写当前工作区的构建/测试必须排空或隔离，不能旧写者仍在、新员工就接着改；冻结快照上的只读服务可在明确重新授权后保留，但旧会话不能再控制它。转交控制 handle 使用新 epoch，历史 producer attempt 不改写。

宿主重启后不凭复用 PID 或 open port 认领进程，需 supervisor 的 job/container identity 与 generation；无法确认则停止/隔离重建或保持 blocked，不猜。收尾撤销预览/借用与测试账号，清理只针对所属服务、缓存和卷，不杀其他公司进程。JobFinished、ServiceReady 与 ArtifactAccepted 是不同事件。

45.5 C-BROWSER：调研、应用验证与安全预览

45.5.1 三条路径不能混在一起

搜索/网页读取：获授权的搜索 MCP 返回发现结果，网页读取使用批准的 HTTP/浏览器访问路径。返回 URL、标题、获取时刻、访问状态、引用片段和内容指纹；搜索摘要不冒充已读原文。输入 URL 不是网站写权限，不执行页面嵌入的“新系统指令”。若没有搜索 provider，只支持明确 URL 阅读并在能力表显示 search=unavailable。

目标应用验证：首版参考隔离 Playwright/Chromium，访问 C-JOBS 提供的特定服务端点。DOM/可访问树、表单交互、可见结果、控制台和网络错误及截图作为测试证据；不因拿到页面就宣称功能正确。W04

供人试用的预览：工作台可以给出已授权的预览定位；不是将任意生成代码当作工作台 React 组件，也不是默认发布公网。第一条闭环可以先交付截图/追踪和本机隔离预览，远程预览必须在独立访问边界通过测试后才启用。

45.5.2 浏览器执行合同

浏览器资源按公司/使命/员工和用途隔离，不附着到管理员平日使用的 Chrome。测试账号、Cookie、storageState 和 bearer handle 只在相应受控环境中保存；不进入原始日志、模型接班包、下载交付物。Playwright 官方提醒，认证状态可能足以冒用账号，必须避免公开提交和不当复用。W05

默认使用无秘密的临时测试账号，按测试要求填充/重置数据。验证码、未知登录和超出授权的第三方跳转进入明确等待；不能自动绕过。浏览器导航、重定向、iframe、下载、WebSocket 与后续资源请求均受网络出口政策约束；只检查最初 URL 的域名不足以形成隔离。创建/删除真实记录仍是外部 Action，不以“点击按钮”绕开副作用管理。

记录 BrowserRun：browser build、执行环境、candidate/服务 generation、输入数据版本、viewport/locale/timezone、步骤、断言、截图/DOM/log/trace 的 Artifact 引用。截图只能证明捕获的画面，功能验证需要操作与断言；模型视觉评价与确定性测试分开，不能把漂亮截图等同全部通过。

拿到图片但无法实际送进当前模型时显示 visual_input_unavailable。可继续不依赖视觉的检查；需要比较参考图时必须使用合格视觉链或由人处理，不能编造“已经看过”。

45.5.3 预览不进入管理员信任域

首版不在工作台同源路径托管生成应用，不在管理页面注入其 HTML/JavaScript。预览使用独立 origin 和隔离浏览器 profile，使用不携带管理 Cookie、令牌或默认登录态的访问路径。仅换端口并不足以完整隔离 Cookie 和所有侧通道；实施必须验证 host-only Cookie、Origin/CSRF、网络拒绝访问控制面和无 opener/非可信消息处理。

预览 Origin/route/generation 有明确生命周期和访问者范围；禁止宽泛 CORS、共享 Service Worker、开放目录和直接暴露宿主端口。需要预览鉴权时，凭据通过独立受限访问机制，不能复制管理员会话或长期 token 进 URL。截图/纯文本作为未具备隔离预览资格时的可用退路。

员工生成的测试应用无法取得控制 DB/管理 API 网络权限；防护不能只依赖浏览器同源规则。关闭预览对新连接生效，已有连接的中止需要真实回执；网络断线不自动把预览发布到另一公网地址。W09

45.6 C-GUIDANCE：人类指导、需求变化与接管交还

45.6.1 工作台是指导入口，QQ 仍只提醒

公司/使命/任务/员工详情提供一个轻量“指导与反馈”输入区，可附已登记资料、引用和具体问题。不要求打开原生 CLI，也不引入另一套聊天数据库。人可直接联系固定员工，消息绑定真实管理员身份与当前 scope；组织成员间的直接协作不变。

类型 处理方式 不应隐式发生
补充资料/建议 保存 Guidance，定向建立待处理责任，在安全边界读取 新建使命、扩大网络、马上打断无关任务
询问进度 默认展示现有事实；明确要求额外分析才准入一次付费工作 每次打开对话框都召唤模型
回答澄清问题 挂到既有 Question/Obligation，记录被采用状态 标记该任务所有验收已经通过
正式需求/优先级变更 用户选择下一边界处理，或先暂停指定工作再处理；形成ChangeRequest/新输入版本与影响分析 自由文本未经确认修改成功标准/金额；未取得停止回执就称已停
管理授权 复用正式命令/确认流程 因写在消息里就获得管理员操作能力

received / queued / considered / applied / declined / superseded 分开：工具确认保存不代表员工已处理；采用一条意见要关联对应任务/版本。公司暂停时消息照常入库，但不被普通通知唤醒；恢复后按版本补齐。人也不会因为直接给前端一句话就获得第二个未协调写会话。

45.6.2 变更不能只改 prompt

ChangeRequest 指定原需求 revision、拟议变更、范围和是否需要阻止旧结果发布。小范围补充可在既定任务中处理；改变正式成功标准、权限或预算须按管理流程确认。程序能计算显式依赖，不能宣称完整理解所有自然语言影响；不确定时固定规划岗做有界分析，关键范围保守阻止旧候选放行。

相关 Task/Input/Contract 生成新 revision，旧候选的受影响批准 invalidated；尚未启动的旧任务取消或 supersede，正在执行的工作在安全边界更新或中断。无关任务继续工作，不为一处按钮文案重启全公司。被替换附件保持历史引用但不再是当前输入。

员工尚未理解需求时提出结构化 Question：具体未知、相关证据、能够继续的部分、期限与预算。没有人回答时保持等待，只有确实阻塞且需要人采取动作时经现有 QQ 规则通知。已经超时/被新变更替代的问题，迟到回答不复活旧任务。

45.6.3 接管写入与交还

首版优先通过受控补丁/新快照导入让人修改，而不是开放在线 IDE。人也可以按明确 CLI 流程在隔离副本工作；不需要对每行改动审批。

人请求 TakeoverLease（指定 task/workspace/外部资源）
  → 暂停相关新派发，排空/停止或隔离相关写者
  → 收到实际交接回执后才把编辑副本交给人
  → 人提交补丁/快照及基线，声明完成
  → 程序核对差异、根目录、当前版本和在途影响
  → 接受新的工作基线，使受影响验收失效
  → 归还租约、重新构造上下文、显式恢复

人工改动要保存 human provenance，计入人类介入时间；不是 AI 的无人产出。补丁针对过期基线不得直接覆盖，先创建冲突或合并候选；导入也不能启用其中的 Skill/MCP/运行脚本。接管超时不自动夺回仍在使用的副本并双写；先核对权限回收，不能安全收回则等待。

管理员直接在系统之外改共享目标时，不能承诺完全阻止；检测 drift 后冻结相关写回，登记外部修改和新基线。只按 Resume 而不核对人改了什么，不满足交还合同。人可结束使命，不必为了让旧计划继续执行而撤回自己的修复。

45.7 C-DELIVERY：可取得、可运行、可反馈的交付

45.7.1 DeliveryManifest 不等于“全部聊天记录打包”

在任务/使命页提供“交付”视图，聚合已有不可变产物和证据。DeliveryManifest 包含 delivery_id/revision、company/mission、源输入与精确代码版本、环境/构建信息、文件清单和 hash/大小、运行说明、验收结果、已知限制、许可/来源说明以及反馈入口；秘密、开发缓存和原生模型会话不作为普通交付附件。

软件交付最少包含 内容/研究交付最少包含
固定源码或补丁、需要的构建件、启动/测试命令、依赖/支持平台、配置说明、验证证据与未解决项 定稿或报告、来源与获取时间、必要素材、可用导出、事实/实验边界及发布状态

构建件必须来自清单绑定的版本/环境；不是把最新目录里找到的可执行文件随手上传。源码交付、构建件交付、通过测试和真实部署是不同状态。第一参考环境是 Linux，不因控制面 Go 可跨平台就说员工产物支持 Windows/macOS。

45.7.2 发布给人、业务验收与人接受分开

交付状态为 assembling / ready / invalidated / withdrawn；人对交付的态度单列 not_requested / awaiting_feedback / accepted / changes_requested。在授权内通过内部验收后，可以自动生成 ready 交付，不要求每个内部步骤人签字。是否必须得到用户接受才能结束使命，在 Mission 合同事先明确；默认不凭沉默捏造 user_accepted。

一次下载、预览或 QQ 消息都不算人验收。需要用户试用时，设置有限反馈期限和到期行为；它不是让模型一直等待的活跃会话。收到修改请求时，在有效使命内生成修订任务；已结束使命只将反馈送入公司 backlog，待人开新使命，不偷偷复活原授权。

45.7.3 安全下载与可重现说明

下载经过后端鉴权，内容以固定 ArtifactRevision 流式提供，明确文件名/MIME/大小/hash；不得将任意磁盘路径直接暴露给客户端。原始 HTML、可执行文件按附件下载，可信的文本/图片预览与运行应用预览分别隔离。导出保留 pin 直到生成/传输阶段安全完成，采用有期限的下载租约而非永久 pin。

交付清单不会让已撤销或已删除资料重新可见；敏感来源不具备导出权时，脱敏或形成有缺失说明的新清单，不能继续称完整可重现。新问题推翻验证结论时追加 invalidation 和新 delivery revision，历史不覆盖。重新构建依赖不可获得时如实说明，不以 hash/lockfile 声称永远可复现。

可配置普通完成通知，但默认 QQ 仍只发接管问题；交付 ready 不等于要新增一条成功推送。终态报告和待决事项在工作台始终可查。

45.8 C-FEEDBACK：来自外界的新工作

45.8.1 首个真实来源选择与执行边界

本版选择GitHub Issues 只读轮询作为首个真实反馈适配目标，复用已授权 HTTP/平台能力，由普通程序调度；不默认扫描用户个人全部仓库，不依赖人工复制每条反馈。安装时选择确切 repository ID/范围、只读凭据、观察起点、筛选政策和预算；没有实际配置时只运行模拟来源或界面手动反馈，不称已接通 GitHub。

collector初读issue标题/正文/状态与指定范围更新；正式triage/修复前再读取单issue的有界评论上下文，保留评论ID/revision、覆盖时间与截断。GitHub提供单issue评论的只读及分页接口。D01 超限/无权时可以观察或等待整理，不据旧正文高置信度实施；评论正文中的命令不变成授权。完整timeline、所有webhook、远端关单/评论/发布关联不默认支持。Issues接口可能返回PR，仍按本profile识别排除。W06

45.8.2 幂等输入与有界覆盖

FeedbackSourceBinding 保存来源身份、权限/过滤 revision、采集游标和 coverage；FeedbackObservation 保存 provider item ID、源更新时间、原文指纹、抓取时间及模式。更新同一反馈产生新观察版本，不反复创建同名新任务；有新相关信息时定向唤醒，只有“仍然 open”不每日唤醒一次。

分清首次基线、完整扫描与增量轮询。使用分页时，页面记录落盘后才能推进该页扫描状态；只有完成本批必要页，才推进可声明的覆盖水位。限流、失联或页失败显示 partial/stale，不把失败页当空列表；按官方分页链接和限流提示有界退避。W07–W08

updated_at 不是唯一 ID 或全局提交顺序。参考实现采用重叠时间窗口和 item ID + 内容指纹去重；必要时周期性有界完整核对。分页过程中列表可能变化，不能宣称快照式无遗漏；明确最终一致覆盖、上次完整扫描和未知删除/权限丢失。不得把 403/404 自动当作用户删除了所有 issue，也不得将不再匹配筛选的记录默认为“问题已解决”。

首版只对选定规模、在限额内可反复扫描的仓库声明资格；无法在轮询窗口覆盖时缩小范围或延长 SLA 并经用户确认，不悄悄丢最后几页。API 请求的 304/ETag 可作优化，但不能替代每页输入记录和覆盖账本。

45.8.3 观察、待办与使命的关系

来源文字先按不可信资料保存，再规则去重/分类。准备正式接手时先按额度取必要评论；未覆盖范围明确partial，评论编辑/更正触发受影响工作核对，不靠标题匹配排除关键信息。无意义重复不调用模型，必要语义判断创建有界triage Task交现有岗位。程序限制请求/正文/评论量，不让外部工单洪峰无限烧钱。

新反馈在有效维护/运营使命中，符合范围才创建或更新正式任务。一次性交付已关闭后，新反馈进入 Company backlog：可以在有单独有限授权的 collection policy 下采集，但不能沿旧使命授权自动启动模型。没有独立采集授权就停止轮询。一个公司仍只占用一个未释放使命。

对外评论、变更状态、提交 PR 属于另外的外部写 Action；首版只读 collector 不拥有这些权限。内部记录“已处理”不得说成远端工单已经关闭。后续需要反馈写回时，另登记目标与幂等/结果核对政策。

45.8.4 保留真实运营指标

反馈来源的 completeness、时延、权限状态与业务质量分开。模型认为修好了，只能指向实际 artifact/evidence；来源后来关闭不一定由本团队修复，必须记录归因边界。公司 backlog 数、有效任务数、已验证修复与用户认可分开，不用“看到 10 条 issue”伪装“解决 10 个问题”。

45.9 数据、员工操作与工作台集成

所有对象依旧存 Go/PG 与现有产物库。新增逻辑记录只包括 InputAsset/Representation/InputBinding、ProjectEnvironmentRevision/PreparationRun、JobRun/ServiceEndpoint/BorrowerLease、BrowserRun、Guidance/ChangeRequest/TakeoverLease、DeliveryManifest/UserDisposition、FeedbackBinding/Observation/BacklogItem。它们复用 Task/Action/Artifact/Usage，不创造另一套预算、员工或事件总线。

45.10 正常工作验收、变体与阶段门

WF-36 是正常工作验收，不是把所有故障一次塞进去。 使用固定的小型现有 Node Web 项目、截图、文本需求、CSV 与文本型 PDF（各件有真实 hash）。现有四个岗位不变；依赖预批准，测试数据无生产秘密，真实模型总预算先由人批准。

G0-JOBS 命令/服务/就绪、日志和换班后核对 不重复启动；旧写者未知则暂停相关写工作
G0-BROWSER 目标应用交互、证据、网络/认证和预览隔离 无浏览器资格不得声称应用实测；截图交付不伪装交互预览
G1-GUIDANCE 指导、变更、人工接管/交还和版本失效 保存输入、明确待处理；无接管回执不共享写权
G1-DELIVERY 清单、鉴权下载、运行说明、用户态与历史保护 不发布残缺 ready；缺平台/环境支持须标明
G4-FEEDBACK 一个真实只读来源、分页/重试/覆盖、使命边界 模拟与手动反馈可先做；不宣称真实无人运营

实施不等待所有 Gate 通过才写代码。第一纵向切片先做文本/图片输入、一个环境、一个 Job、一个服务、最小浏览器验证、一个可下载结果；PDF/CSV/ZIP 和外部来源在相应阶段补齐后才声明支持。工具栈无需重新选型，未批准权限/费用不因赶阶段而自动开放。
