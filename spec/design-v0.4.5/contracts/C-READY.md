## 36. C-READY：开工前门禁、第一条纵向闭环与可证伪目标

### 36.1 现在已经定下来的事情 <a id="subsection-36-1"></a>

新内核按 Go + PostgreSQL + Web SPA 实施，不同时维护 SQLite、另一个通用工作流引擎或双数据库测试路径。固定 Company/Employee/Mission；一个公司一个活跃使命；一个员工一个活动控制 epoch；职责不自适应改写；有工作才调用模型；组织事实独立于模型和会话；开发与独立审查不能相互替代。

本版契约 C-EXEC / C-AUTHORITY / C-SLEEP / C-REVOKE / C-MEMORY / C-RETRY / C-UPGRADE / C-READY 是实施前规则。未通过实验不得自行绕开，只能停下记录阻塞或通过 ADR 改设计。

### 36.2 G0 的有限实验证据，而非无限选型 <a id="subsection-36-2"></a>

### 36.3 第一个真实软件任务 <a id="subsection-36-3"></a>

固定四岗位：规划/架构、后端、前端、验证。测试仓库里实现分页查询与筛选，在至少三个里程碑内修改 API、前端和测试。初始授权只覆盖指定测试分支，不包含生产主分支或外部发布。

必须注入：工作中的合同修订；一条需要回复的横向请求；模型额度耗尽而无法写临终总结；一个仍在运行的测试；旧 epoch 迟到结果；一次候选 review 后代码变化。结尾自动组合、完整相关检查、按既定授权验收。

未完成承诺保持、过期批准拒绝、同工号无双写者、实际产物满足外部验收，这是确定性期望；模型能否首次做对和成本是否更低则作为实测结果报告。不能人工修完后隐藏在“无人监督”成绩里。

### 36.4 第一批验证目标与范围 <a id="subsection-36-4"></a>

内核：运行 FT-01～56 中每个声明支持模式对应的测试，并对 wake/撤权/事件顺序/预算场景做多种调度交错。示例压力参数可设 10,000 次重复事件、1,000 次唤醒竞态；这些是候选 fixture 规模，不是已完成测试或正式容量保证。

真实模型：先完成短闭环、再数小时、多次接班，最后连续多天。失败率、接班时间、读取重复资料量、人工介入、总成本全部报告。不能用“模拟时钟前进七天”声称七天真实自治。

经济门：在相同预算和验收下，多 Agent 的收益可以是更少人类接管、更可靠结果或更短时间；不是必须比单 Agent 便宜。但若额外成本没有换来任何目标收益，就保留单 Agent + 顺序审查路径，不靠加更多员工掩盖问题。

### 36.5 准入清单与停止点 <a id="subsection-36-5"></a>

开始有限骨架开发之前：本版契约已接受、fake 接口和测试数据可用、版本规划与权限模式明确。开始真实付费实验之前：模型正常授权、金额和时间窗获批、输出不接生产、未知费用口径明确。对外宣称某能力之前：对应真实测试、失败报告与支持矩阵齐备。

时间盒优先验证最高风险假设，不保证四个月完成全部愿景。按R1/R2/R3收缩功能面但不删除已开放能力的接班、休眠、直接协作、验收、撤权、预算或持久性。未决事项还包括组织增益、行为接班与上手/维护负担等产品假设，并非只剩版本和账号。主数据库等实现基线不交给每个子Agent重新选择；试验失败时可经明确决策改方案，不暗改产品定位。
