## 29. C-EXEC：执行链资格与强约束边界

### 29.1 唯一首个参考链 <a id="subsection-29-1"></a>

**单 Linux amd64 控制宿主 + 同机 PostgreSQL 18 + Go daemon + 固定版本 Codex app-server + 可验证 worker 环境** 为第一条实现路线。Windows 使用 WSL2/Linux VM 做该链的验证，而不是声称 Go 能交叉编译就等于所有 OS 的隔离保证相同。macOS 可以作为 Web 管理客户端；ARM64/native macOS/native Windows 执行逐项后验，不纳入首轮强保证。

这是实施决定，不表示此处已完成安装。具体 Linux 发行版、内核/cgroup/容器版本写入 ExecutionQualification。Rootless 容器只是一种拟采用工具，必须通过权限与停止测试才标为 restricted。[N10](../ARCHITECTURE.md#ref-n10)

### 29.2 资格是多个维度，不是一个布尔开关 <a id="subsection-29-2"></a>

| 维度 | 需要记录的证据 | 缺失后的行为 |
|---|---|---|
| 协作输入 | 活动 turn/boundary、送达确认、过期 turn 处理 | 声明真实延迟；不能满足任务要求就拒绝 |
| 进程停止 | 请求 ACK、进程树停止、孤儿进程、隔离证据 | 不能重启第二写者 |
| 文件隔离 | 他公司目录、控制 DB、宿主目录、符号链接逃逸 | 不能标 restricted |
| 网络隔离 | 只允许许可目的地、拒绝直接发布或隐藏调用 | 关闭相应外部功能或明确 trusted |
| 凭据隔离 | 工具凭据不进入 prompt、日志、导出包和不受控 shell | 未证实不能宣传密钥隔离 |
| 预算可见 | 请求数、token、在途费用、原生子代理边界 | limited；严格精确模式拒绝 |
| 迁移能力 | 同 harness 异模型 / 跨 harness / 跨供应商分别测试 | 未测级别显示 unverified |
| 产物验收 | 工具原始回执、准确版本、只读审核、集成基线 | 保持 candidate，不自动 accepted |

同进程/同 UID 的原生 shell 可能读到 harness 配置、环境变量或认证文件；“凭据没有写进 prompt”不证明它读不到。需要通过执行分离、作用域凭据或可验证网关解决；做不到时不偷偷给一个装饰性 SecretRef 声称问题已解决。

### 29.3 Action 网关的覆盖范围 <a id="subsection-29-3"></a>

所有受本项目治理的副作用都应有 ActionIntent；但若 harness 原生工具绕过网关，就只能对真正被截获和限制的路径作保证。初期对自有测试仓库允许可回滚本地文件改动；外部发布/生产写访问默认无凭据、无出口。

重要外部操作必须经过可识别的授权和结果核对；不能用 shell 文本正则推导完整语义安全。模型自己的 API 连接也要计入目的地策略，但不私自读取或转发订阅 token。认证沿厂商正常支持的路径接入。

### 29.4 G0 不花大额度也能验证的内容 <a id="subsection-29-4"></a>

fake worker 与模拟外部服务先验证消息、停止、重复回执和边界。随后只在明确批准的小预算内验证真实模型的活动输入、工具结果、接班与中断。全链测试记录版本指纹；上游升级后重跑关键资格测试。不得以 TUI 自动敲键代替可编程契约后仍宣称稳定兼容。
