### 45.7 C-DELIVERY：可取得、可运行、可反馈的交付 <a id="subsection-45-7"></a>

#### 45.7.1 DeliveryManifest 不等于“全部聊天记录打包” <a id="subsection-45-7-1"></a>

在任务/使命页提供“交付”视图，聚合已有不可变产物和证据。`DeliveryManifest` 包含 delivery_id/revision、company/mission、源输入与精确代码版本、环境/构建信息、文件清单和 hash/大小、运行说明、验收结果、已知限制、许可/来源说明以及反馈入口；秘密、开发缓存和原生模型会话不作为普通交付附件。

| 软件交付最少包含 | 内容/研究交付最少包含 |
|---|---|
| 固定源码或补丁、需要的构建件、启动/测试命令、依赖/支持平台、配置说明、验证证据与未解决项 | 定稿或报告、来源与获取时间、必要素材、可用导出、事实/实验边界及发布状态 |

构建件必须来自清单绑定的版本/环境；不是把最新目录里找到的可执行文件随手上传。源码交付、构建件交付、通过测试和真实部署是不同状态。第一参考环境是 Linux，不因控制面 Go 可跨平台就说员工产物支持 Windows/macOS。

#### 45.7.2 发布给人、业务验收与人接受分开 <a id="subsection-45-7-2"></a>

交付状态为 `assembling / ready / invalidated / withdrawn`；人对交付的态度单列 `not_requested / awaiting_feedback / accepted / changes_requested`。在授权内通过内部验收后，可以自动生成 ready 交付，不要求每个内部步骤人签字。是否必须得到用户接受才能结束使命，在 Mission 合同事先明确；默认不凭沉默捏造 user_accepted。

一次下载、预览或 QQ 消息都不算人验收。需要用户试用时，设置有限反馈期限和到期行为；它不是让模型一直等待的活跃会话。收到修改请求时，在有效使命内生成修订任务；已结束使命只将反馈送入公司 backlog，待人开新使命，不偷偷复活原授权。

#### 45.7.3 安全下载与可重现说明 <a id="subsection-45-7-3"></a>

下载经过后端鉴权，内容以固定 ArtifactRevision 流式提供，明确文件名/MIME/大小/hash；不得将任意磁盘路径直接暴露给客户端。原始 HTML、可执行文件按附件下载，可信的文本/图片预览与运行应用预览分别隔离。导出保留 pin 直到生成/传输阶段安全完成，采用有期限的下载租约而非永久 pin。

交付清单不会让已撤销或已删除资料重新可见；敏感来源不具备导出权时，脱敏或形成有缺失说明的新清单，不能继续称完整可重现。新问题推翻验证结论时追加 invalidation 和新 delivery revision，历史不覆盖。重新构建依赖不可获得时如实说明，不以 hash/lockfile 声称永远可复现。

可配置普通完成通知，但默认 QQ 仍只发接管问题；交付 ready 不等于要新增一条成功推送。终态报告和待决事项在工作台始终可查。
