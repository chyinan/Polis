## 33. C-MEMORY：错误记忆、影响传播与保留策略

### 33.1 纠错是一个有证据的工作流程 <a id="subsection-33-1"></a>

禁止把原记忆静默覆盖成另一句话。CorrectionRequest 指向旧 record/revision、纠正证据、作用域、提出者与影响类别。普通成员可以提出；内核或指定审核按类型确认，生成新 revision，将旧内容标记 disputed/superseded。

关键事实和合同的引用通过 MemoryDependency 保存；接班包、PlanRevision、Artifact/Evidence 记录使用的关键来源。旧来源失效时，系统能确定性标记显式依赖对象 `needs_revalidation`，新上下文不再默认使用它。

**只承诺显式依赖闭包，不声称自动理解所有自然语言隐含关联。** 无法确认影响范围时，建立受限核查任务；高风险范围保守冻结，低风险无关工作可继续。

### 33.2 摘要不能凌驾于权威记录 <a id="subsection-33-2"></a>

Task/Obligation/Action 的责任状态来自相应权威表。摘要遗漏一项承诺，不能导致任务消失。verified 表示通过了某个已记录的方法，不等于绝对真理；所有事实保留观察时间与适用范围。

摘要生成和事实升格是两个动作。执行模型可以写“我认为 X”，不能仅因写入记忆接口就获得 `verified`。新闻来源转述、其他 Agent 转发和一次模型评审都是来源数据，不升级成系统政策。

### 33.3 纠正已经进入活动模型上下文的错误 <a id="subsection-33-3"></a>

数据库里标失效并不让活动模型自动遗忘。内核将相关任务标 dirty，并在高风险动作/验收门禁检查依赖版本。可送达纠正信息且风险低时按工作边界重验；涉及关键权限或安全前提时，暂停相关执行，核对在途动作，重建干净上下文再继续。

一般纠错不冻结整个集团；隔离到明确 Company/Mission/Contract 范围。原生会话缓存若仍含不可安全消除的错误假设，使用中立接班路径，不强求原生 resume。

### 33.4 数据保留分类 <a id="subsection-33-4"></a>

| 数据 | 默认管理原则 | 不允许 |
|---|---|---|
| 活跃任务、承诺、未知动作、当前政策 | 必须保留到闭合及审计期限 | 为省空间删掉唯一恢复依据 |
| 验收证据、产物、关键来源 | 引用计数/保留 pin 与版本清单 | 删除后继续展示通过或可重放 |
| 模型原始文本、详细日志 | 受敏感度、容量和明确期限约束 | 默认无限保存所有内容 |
| 可重建摘要、检索索引、编译缓存 | 可清理、可重建 | 删除时误伤事实/未提交必要工作 |
| 凭据、私有登录状态 | SecretRef/宿主管理边界 | 混入上下文、备份、跨公司导出 |

具体原文保留天数在安装配置和使命合同确认，不能用一个未经用户批准的默认值擅自扩大存储。后台 GC 以活跃任务、未闭合责任、备份清单 pin 为根；先标记、后回收，处理并发新引用。清理不可逆操作需要其管理授权。

### 33.5 删除与审计冲突 <a id="subsection-33-5"></a>

敏感内容删除后可以保留不含原文的 tombstone、hash 和操作说明，但必须披露相应证据将不再完整可重放。不能同时承诺“立即不可恢复删除原文”与“永远完整恢复所有上下文”。历史备份中的删除传播按明确保留/销毁策略处理；恢复旧备份时应用当前删除与撤销清单，不把已删秘密重新上线。
