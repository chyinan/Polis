### 42.5 C-RESOURCE：实际资源归属与行动粒度 <a id="subsection-42-5"></a>

#### 42.5.1 配置别名不是资源身份 <a id="subsection-42-5-1"></a>

引入 `ResourceBinding` 与规范化 `ResourceKey`：记录 provider/environment、实际外部 ID、目标对象、读写类别与公司授权。仓库优先使用平台仓库 ID + 目标 ref；本地目录同时核对已批准根目录与运行时实际文件边界；内容发布使用平台、应用和实际账号上下文。不能仅按用户填的 URL/别名判断隔离。

同仓库的 HTTPS/SSH 别名或两个公司指向同一个共享分支，必须识别或阻止歧义写入。无法证明两个别名是否同一目标时不宣称独占保护；保守要求人确认映射并在执行前复核。

首版对共享分支、部署目标、发布账号等需独占业务写入的资源只允许一个当前所有者。冲突拒绝，不立即实现跨公司谈判。只读共享可另授；模型 provider 账号是受共享容量/预算管理的资源，不等于要独占整个账号。QQ 通知 bot 也可由多公司共用一个受控发送器，但每个接收目的地的可披露公司范围单独授权，不让员工直接使用该账号。

独立 clone/工作区内的并行开发仍可进行；严管的是共同受影响目标。租约过期不证明旧工具停止；ResourceKey 所有权转交必须连同旧写者隔离证据和资源 epoch。

#### 42.5.2 三档动作边界 <a id="subsection-42-5-2"></a>

| 类别 | 示例 | 首版治理方式 |
|---|---|---|
| 只读观察 | 读取已授权文件、取执行状态 | 会话权限/查询大小/来源规则；不因此调用模型 |
| 受限环境内本地工作 | 编辑隔离 clone、在无凭据环境跑测试 | Task/Attempt 授权 + 可验证隔离 + 观察/检查点；不每改一行都跑发布审批 |
| 共享或外部效果 | 更新共享分支、发布、部署、QQ 通知 | 受控 ActionIntent、现行授权、单次派发/核对；用途特定的权限和数据规则 |

QQ 通知属于控制面授权的运维外发，不是员工的业务工具；员工休眠、普通业务暂停或模型额度为零，不妨碍已授权的通知发送。人单独关闭外发/撤销通知授权则必须停止新通知；它不能借“紧急”绕过凭据和接收者范围。

#### 42.5.3 审查不是“所有目录都不可写” <a id="subsection-42-5-3"></a>

审查输入是冻结、只读的候选代码快照；编译输出、测试临时文件、缓存放独立有界 scratch。验证前后核对输入 hash，防止测试脚本修改候选后仍称原版本通过。被审代码及脚本同样不可信，验证进程不能读管理凭据或突破网络/文件限制。

固定 Reviewer 若提出测试补丁，将其作为独立候选变更；不能修改生产候选、随后以同一员工身份批准修改后的结果。需要时交其他独立验证入口或有权人决定，不自动创造新岗位。
