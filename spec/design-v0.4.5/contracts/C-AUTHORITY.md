## 30. C-AUTHORITY：固定岗位、决策权与最小组织制度

### 30.1 职责不变，任务可以变化 <a id="subsection-30-1"></a>

首版固定人类管理者、规划/架构、开发、验证/审查岗位。任务只在原岗位能力和权限内分配，模型替换不改变岗位。公司模板不包含自动招聘、裁员和自调岗算法。

| 事项 | 可提议者 | 决策/执行方式 | 不允许的捷径 |
|---|---|---|---|
| 新增里程碑、拆分近期任务 | 固定规划员 | 内核检查使命、预算、依赖与职责；授权范围内接受 | 超出使命却伪装成一个子任务 |
| 同事协作请求 | 任何有相应通信权限的成员 | 接收者记录 Obligation；需要新工作时按既定队列准入 | 发送者强制抢占别人当前任务 |
| 普通任务优先级调整 | 规划员或授权人 | 版本化计划；内核检查资源与进行中约束 | 员工群聊里自发修改全局顺序 |
| 接口/规范变更 | 相关领域员工 | 提议新 ContractRevision；按风险规则批准 | 将提议当作已经生效的事实 |
| 提交产物 | 当前任务执行者 | 保存版本化产物，进入 candidate | 自填 acceptance_passed |
| 严重缺陷阻塞 | 固定审查员按职责 | 有定位/证据的请求触发内核冻结 | 单凭情绪无限阻塞所有公司 |
| 解除阻塞 | 指定审查/有权管理路径 | 新证据或显式记录的例外决定 | 规划员为赶工自动忽略安全检查 |
| 扩大预算、权限、使命目标 | 成员可请求 | 人类在管理接口批准新版本 | 相互投票获得提权 |
| 运行时/策略引擎升级 | 员工可提交改进 | 外部可信发布流程；维护窗口安装 | 在自己的任务里热替换监管程序 |

### 30.2 协作不需要组长传话，但派工不能无政府状态 <a id="subsection-30-2"></a>

同事可以直接询问、分享变更、报告失败。请求有明确类型、作用域和期望动作；接收者可以按约定接受、说明拒绝或提出阻塞。普通请求不自动升级为 P0，不自动暂停当前写操作。只有内核确认的风险事件才立即冻结相应外部动作或验收。

工作已占槽时，新的行动请求进入持久待办，按安全工作边界处理；等待须有 WaitCondition，不因未满足的旧待办反复唤醒；不为同工号启动第二个并行写会话。限时无法解决则向固定规划/架构岗提交差异、反例和影响，不将整段争论转发给所有人。

### 30.3 独立审查以来源和责任判断，不以模型名判断 <a id="subsection-30-3"></a>

同一个作者换模型、换会话或换任务 ID，仍然是该产物的作者来源。需要独立审查的任务必须交给固定的不同员工或有权人；审查员若实际修改了产物，相关部分重新需要独立验收。

只有一位执行成员被调度时，独立审查可以随后顺序执行；不能因此降低原合同。完全不要求独立审查的低风险任务可由确定性工具验收，但必须在任务启动前明确，不在失败后删要求。

### 30.4 计划接受不等于计划必然正确 <a id="subsection-30-4"></a>

内核能校验职责、版本、资源和图结构，不能通过 schema 证明策略有用。计划质量仍由阶段证据、领域评价和外部反馈检查。使命修改是新授权，策略修订不是新增权限。关系表必须能回答“谁提出、谁接受、根据什么规则、何时生效”。

**关联：REQ-01/08/10/12/14；FT-19、25、28、38、39、55。**


### 30.5 启动职责与员工调用 <a id="subsection-30-5"></a>

首次规划由程序创建固定模板任务并唤醒既定规划员；不是临时创建老板 Agent。员工日常操作采用 employee-ops@1，实际身份由会话认证绑定；规划员的会话失效不删除其同事。QQ 接收者不能以聊天文本行使人类管理权。详见第 42.2～42.4、42.7 节。

### 30.6 固定模板也必须覆盖现实工作 <a id="subsection-30-6"></a>

创建时检查任务类型→负责人→决定/独立验收路径。planner可承担计划/需求收敛，backend承担后端与受限环境计划，frontend承担前端/交互，review承担独立检查；有限交叉检查须在初始RoleRevision声明，不靠运行时换帽子。测试覆盖层的审查不等于自批生产候选，可信验收基线由人/外部流程固定。缺合格独立路径的任务在准入时明确需要人，不能承诺全自治，见46.6及product/TEAM_COVERAGE.json。
