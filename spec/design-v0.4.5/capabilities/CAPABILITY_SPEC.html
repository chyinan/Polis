44. 工作环境与能力配置：工作区、共享 Skills、MCP

44.1 本轮结论与首版范围

每位固定员工均应能自行发现并读取其获授权的工作区文件、公司共享资料和公共 Skills，并使用被批准的 MCP 工具与资源；无需规划员转发。 这里的“每位”指共同具备访问入口，不是所有员工自动拥有所有数据与写权限。人可在建公司时通过岗位模板批量赋予所需基础权限，授权内的日常读写和工具选择不逐次打扰人。

本轮在 0.4.2 上补齐此前未完整定义的资料柜与工具入口，不改变固定岗位、不引入自动招聘。员工能自主选择获授权的手册和工具，不等于它能自行改变职业、安装任意服务或获得新权限。Go/PostgreSQL/React、QQ 主动接管通知及办公室延期均保留。

完整能力目标包括工作区操作、公共/公司Skill登记/固定/加载/受控脚本、stdio与Streamable HTTP MCP、逐工具授权及持久环境接班。R1先实际接通选定Skill与一个合格stdio服务；R2补受控远程服务与完整管理路径，分别验证两类传输。不承诺任意第三方服务兼容，未实现范围保持显式不可用而非假支持。

不纳入首版：技能市场、未授权/加载时隐形联网安装依赖、模型自行启用新增能力、全集团无隔离共享浏览器、通用 MCP Apps/嵌入式第三方 UI、服务请求模型采样、任意递归代理与自动 OAuth 授权。只有在额外流程和资格实测齐备后才另行扩展。

44.2 四类概念不能混用

概念 是什么 不是什么
Workspace / Shared Reference 员工可操作的任务工作副本、冻结参考资料和共享产物 全宿主任意文件访问；所有员工同时写同一仓库
SkillRevision 一份带说明、附属文件和可选脚本的版本化工作手册 自带管理员权限的代码插件；新的员工岗位
MCPServerDefinition 经管理者登记的服务连接和运行定义 已授权所有工具；一个所有公司共享的万能进程
EmployeeCapabilityBinding 指定员工可用资源、Skill 版本及 MCP 能力的持久配置 永久执行凭证；可以带着旧权限任意换后端

Agent Skills 的格式由 SKILL.md、YAML 元数据和可选附属文件组成；说明、脚本、参考资料可以分层加载。其 allowed-tools 是实验性格式字段，不能替代本项目的权限判定。S01 MCP 是服务交互协议，工具发现与调用只是通信能力，不自动授予业务权限或文件系统隔离。S03–S07

本章所有 workspace.*、skills.*、tools.* 等名称是 employee-ops@1 的本项目逻辑操作；不是要求第三方 MCP 或 Coding CLI 原生使用这些名字。映射由适配器生成，内部工具句柄不能由模型随意构造。

44.3 C-WORKSPACE：文件发现、访问、共享与路径安全

44.3.1 四层目录与稳定逻辑引用

区域 员工默认体验 生效边界
任务工作区 开发员工可列目录、搜索、读取，按当前任务授权编辑；知道自己的实际执行路径 每个可写环境有明确拥有者与 epoch；非全宿主 HOME
公司共享资料 获授权成员直接读取需求、合同、资料和已发布快照 共享的是固定 revision；写入走提交/发布，不人人改“当前版本”
集团公共目录 管理者登记一次，模板批量选择 Skill 和公共参考资料 只读、明确共享范围；公司专有内容不自动向集团公开
控制与凭据目录 不提供普通员工入口 DB、管理 socket、模型认证、QQ 密钥及其他公司私有目录不得挂载给员工

运行时保存 workspace_id、root_binding_id、公司/使命/员工归属、读写类别、来源 revision 和挂载状态；员工使用稳定逻辑引用，具体物理路径由可信执行环境解析。换宿主或换模型不靠硬编码 D:\\...、/home/user/... 恢复。

可以向工作中的员工展示其沙箱内真实路径，以便现有代码工具使用；不能把一个 workspace://... URI 假装成 shell 已能访问的路径。读取 API 与实际挂载是不同资格项，均要有结果与错误说明。

公共目录布局示意（本项目约定，不是 Agent Skills/MCP 强制规定）：

管理员选择的公共来源目录/
  skills/<skill-name>/SKILL.md
  skills/<skill-name>/references/...
  mcp/<server-id>.yaml                # 仅连接草案，不放明文凭据

运行时受控存储/
  library/approved/<package-id>/<revision>/   # 已确认只读快照
  companies/<company-id>/references/         # 共享引用与已发布资料
  companies/<company-id>/workspaces/<id>/    # 独立任务副本
  companies/<company-id>/scratch/<attempt>/ # 有界临时输出
  control/                                  # 对 worker 不可见

来源目录可位于维护者已有技能库；“选择该目录”不等于全目录递归授权。扫描上界、可导入类型和选中的条目都要明确。目录扫描只登记候选，不执行脚本、不启动 MCP、不联网下载包。配置变更由人确认；已批准版本变成不可变快照后使用，不把可变来源目录原样给所有成员永久挂载。

44.3.2 文件操作的具体合同

统一提供 workspace.list、workspace.search、workspace.read，返回有限结果、相对路径、类型、来源与内容 revision、是否完整及继续读取游标。workspace.snapshot 在有权工作范围内请求固定快照，沿既有 Artifact staging→ready 流程；共享仍由 artifact.submit 和相应发布规则完成。

context.read 继续负责已登记的资料/证据/Skill 附属文件引用。文件改写由已认证的原生编辑工具或受控本地工具执行，不为每行代码创造外部发布级审批。多读者可读取同一冻结资料；不同写者不能共享一个未隔离的可写工作树。

同事需要当前未提交进度时，原拥有者可提交注明 draft_not_accepted 的只读快照；接收者直接读取该引用。实时文件通知只能表示“可能变化”，不保证整棵目录已形成一致快照。工作中的可变文件若发生版本竞争，返回 changed_during_read 或明确的读取版本，不能与另一个版本拼出假内容。

搜索先按权限确定可访问根和路径，再索引/排序；截断、二进制、不支持编码和无权访问分别显示。.gitignore 和排除构建目录只是性能规则，不是保密保证。密钥不应出现在开放根内；额外排除 .env 等名称只是纵深措施，不能声称任意命名秘密都会自动识别。

44.3.3 路径穿越、链接和读取后执行

每次实际打开或写入时，使用受控根内的路径解析和文件句柄边界；不采用字符串前缀检查后再无保护打开的方式。拒绝 .. 逃逸、根外绝对路径、非法 URI 编码以及解析前后对象被替换的情况；符号链接、硬链接、挂载点、特殊设备/FIFO/socket 按宿主资格策略处理。首版导入包默认拒绝链接和特殊文件；可写 clone 的链接支持必须单独测试。

目录/文件名和搜索计数也属于受权限控制的数据；拒绝访问时不泄露另一个公司的名称或存在性。文件写入和恢复沿既有 incarnation/epoch/资源租约管理，不能只在 UI 隐藏入口。

“只读挂载”只保护该挂载的写入，不阻止执行已经读出的代码。整个执行环境的文件、网络、进程和凭据隔离才是安全边界。已打开文件描述符、已加载上下文不能靠删除挂载配置立即收回；撤权必须核对旧进程/句柄，必要时停会话、隔离环境再重建。

44.4 C-SKILLS：公共手册、固定版本、按需加载

44.4.1 来源、审批与名称

技能来源包括集团公共目录、公司专用目录和项目携带目录。来源、作者标注和许可证仅是元数据；不因在公共目录、含 license 字段或出现在仓库里就获得可信/可执行状态。

登记流程：扫描候选 → 校验目录与元数据 → 固定内容清单与指纹 → 管理者确认共享/执行范围 → 发布 SkillRevision → 岗位模板或员工绑定明确引用。 已批准的一批低风险技能可在建公司时统一选择，无需每次使用再审批。

首次格式以 Agent Skills SKILL.md 为兼容目标。S01 本项目保留原始文件，并以严格、安全的 YAML 解析和诊断处理格式错误，不悄悄改写后当作原作者版本；不允许不受控 YAML 对象构造、重复关键键或无限别名展开。轻微兼容问题可在导入 UI 中生成待确认修订，不自动执行其内容。

标识使用 (publisher_scope, package_id, revision)，而非仅用 name。同名集团、公司或项目 Skill 不自动覆盖；人在绑定中选择确切来源。Agent Skills 客户端指南讨论了跨目录发现和分层加载，也提示项目级内容的信任问题；本项目刻意不沿用无提示的项目优先覆盖规则，防止仓库中的同名技能替换已批准手册。S02

项目中新增 .agents/skills、.claude/skills、AGENTS.md、MCP 配置或类似文件，均不能创建公司政策、提权或偷偷启用服务。原生 harness 的自动发现行为必须列入资格测试：只暴露经确认的能力，无法约束未经确认的插件/脚本加载时不标 restricted。正常项目说明仍可作为较低信任资料阅读，不能反过来改写管理规则。隔离安排不得偷偷修改被验收的候选代码字节来伪造测试基线。

44.4.2 不把整座技能库塞进每个员工上下文

活动会话先得到权限过滤后的技能目录摘要，包含用途、资格限制、稳定引用和版本。需要时调用 skills.load 读取正文；再通过明确引用读取 references/、assets/ 或脚本说明。技能数量很多时分页/检索，不能让目录摘要挤掉使命、权限和未完成责任。

skills.load 记录本次上下文使用了哪个 revision 和内容指纹，不自动执行脚本，也不提供新权限。相同会话重复加载可返回已载入引用，换新上下文时按任务需要重新提供正文；“上一模型读过”不等于新模型已经知道。关键使用记录进入接班包，允许按引用按需重读，不默认重扫整个项目。

对于人预先规定必须执行的审查步骤，任务合同记录所需证据；“员工加载过 Skill”不等于它遵守了步骤，更不等于产物验收通过。正文中的业务建议和工具结果均不能覆盖受保护的目标或政策。

44.4.3 脚本不是隐形安装器

说明文件可读取，脚本执行需要另一项工具能力。运行入口由程序绑定确切 SkillRevision、相对脚本路径、摘要、解释器/工具环境、argv 结构、工作根、允许网络和资源上限。禁止让模型提交任意 shell 命令当“技能名称”；不执行未批准的安装钩子，不在第一次加载时偷偷 pip install / npm install / 拉取镜像。

依赖由受信构建/环境准备流程按锁定版本准备；批准政策内可自动执行项目依赖安装（C-ENVIRONMENT），禁止加载技能时隐形安装或多个员工并发修改同一依赖目录。缺依赖可创建有界环境准备任务。脚本包的格式支持不等于每种解释器都已支持；首个 Python/shell 等组合按环境资格逐项验收。

Skill allowed-tools、README 中“必须给管理员权限”、脚本自报只读都只是信息。脚本可以读取什么、能连接哪里、能否改共享目标，继续由 Workspace/Tool/Action 管理。skills.load 的每次调用不需要人审，越界执行请求才按现有升级规则处理。

即使提供 scripts.run 白名单，也不能声称阻止了有通用 shell 的员工重新抄写同等逻辑；严格保证建立在实际 OS/网络/凭据限制上，而不是脚本名称白名单。远程依赖和外部数据使用的额外费用、许可与来源在实施时登记。

44.4.4 更新、撤销与故障

已运行 Attempt 固定 SkillRevision；来源目录变动只产生候选更新，不原地替换已批准文件。更新以新 revision 发布，人在公司/岗位绑定中确认生效边界。新建公司可选新版本，已有使命不因为模板更新而默默换手册。

普通更新在任务/会话安全边界应用；安全撤销优先于版本固定。被撤销版本不得继续新加载或派发关联脚本；活动上下文污染按 C-MEMORY 重建。版本固定不是不可撤销授权。旧产物保留来源，但相关验收是否需重做依据显式依赖和风险规则。

能力缺失时，先记录具体阻塞和可安全继续的工作；只能使用预批准、满足同一需求的替代能力，不能为了继续工作自动下载同名 Skill 或放宽网络权限。

44.5 C-MCP：连接定义、能力发现与受控调用

44.5.1 一套能力中介，不增加第二个调度系统

在 Go 控制面中增加 CapabilityService / MCPBridge 模块，使用官方 Go MCP SDK 作为首选协议实现；SDK 精确版本、实际支持的协议/传输在 G0 资格清单固定。S08 不把完整 Agent 框架、Node 服务或 Python 运行时加进控制面；某个本地 MCP 服务自身需要 Python/Node 时作为独立受限工具环境管理，明确其安装与存储成本。

固定员工会话
  → 受认证 employee-ops 能力入口
  → 当前绑定 / 角色 / 资源 / 数据出口 / 费用 / 行动规则
  → 文件适配、Skill 加载、MCPBridge
  → 本地受限 MCP 进程 或 获授权远程 MCP 服务
  → 结果验证、来源记录、必要 Action 核对

首版受控默认走运行时中介路径：员工不直接获得上游 MCP 凭据，协议和工具目录由中介解析。harness 若需 MCP 接口才能使用工具，可以只连接本项目受控员工入口，再由该入口连接第三方服务。这两个方向的 MCP 连接及身份必须分开。

原生 harness 直连外部 MCP 可作为未来资格路径，不能作为首版默认旁路。若确需采用，必须证明同等身份、调用/数据出口约束、撤权、用量和恢复；否则只标 limited/trusted 或拒绝该使命的强约束模式。不能同时暴露中介和未受限原生入口，形成“绕开就能用”的第二条路。

44.5.2 协议版本必须真实协商，不把旧握手写成永恒事实

截至本次定向查阅，MCP 官方版本页列出的 current 是 2026-07-28；新版本使用逐请求版本信息和 server/discover，并为 2025-11-25 及更早握手式版本定义兼容路线。S03 因此本章不用“所有 MCP 必须 initialize 后维护协议 session”的单一路径。

本项目的支持目标按 profile 区分：mcp-2026-07-28 为当前规范路径，mcp-2025-11-25 为明确的兼容路径。只有 SDK、服务与传输组合实际通过测试才在安装清单里启用；不宣称已实现两者，也不凭文档给 SDK 编造版本。profile 之间转换只发生在 MCPBridge，禁止混用请求元字段、结果类型、旧 session ID 和新能力发现语义。

在任何外部业务动作前固定连接协议和工具目录。可按官方兼容流程探测，但不可把不支持版本的写调用静默换协议重发；没有共同且已批准的 profile 就返回 unsupported。新增协议 profile 不改变 Employee/Task/Action 身份。

44.5.3 配置登记、实际发现与员工使用分开

操作 是否执行外部代码或产生网络访问 是否调用模型
查看已存目录、编辑连接草案、保存禁用配置 否 否
扫描本地配置/Skill 文件 只读受控来源，有限扫描 否
明确的 MCP 连接资格检查与工具发现 是：stdio 会启动程序，HTTP 会访问服务，可能有外部成本 不应调用模型；服务隐含 AI 成本另行声明
员工查询已批准工具目录 只读缓存与权威绑定，不自动连接/安装 不额外触发模型请求
获授权员工发起实际工具调用 按本地/远程、读写及费用政策执行 员工已经在工作；服务内部是否调用 AI 由能力声明和预算另计

本地配置保存可执行物引用、固定参数模板、镜像/依赖指纹和 SecretRef 映射；HTTP 配置保存受管理 endpoint、认证模式和允许的目标范围。不从任意仓库的 mcpServers 配置自动启动进程，不读取原生配置中的秘密并复制到公司文档，不把公共目录变成插件安装市场。

stdio 和 Streamable HTTP 是标准传输类别，但连接本身不构成认证或执行安全保证。S04 资格探测也需要明确的执行/网络授权；不能用户展开工具列表就运行不可信服务器。runtime 模式连接失败不回落到“模拟工具可用”。

44.5.4 授权到工具、资源、目标和副作用，不只到服务名字

MCPServerDefinition 是公共定义；MCPBindingRevision 是公司/员工的独立使用授权。有效能力是以下交集：集团政策 ∩ 公司授权 ∩ 岗位 ∩ Mission/Task ∩ 当前员工 epoch ∩ 执行环境资格 ∩ 工具/资源约束。目录隐藏不能替代调用时重验；没有绑定不能以“公共服务”名义调用。

工具内部标识使用 (server_definition_id, binding_revision, upstream_tool_name, descriptor_digest)，不能仅按 search、delete 等短名。serverInfo.name 也不是全局唯一身份。输入输出 schema、工具说明与路由映射有固定指纹；远端自称 readOnly/idempotent 只是提示，不是可信政策。MCP 工具规范要求对不可信服务的工具注解保持不可信处理，并区分协议错误与 isError 工具错误。S05

风险分类由管理员维护的能力政策和实际接入证据决定；未知语义默认禁止有副作用的自治调用或等待确认，而不是默认只读。数据库读取、搜索和远程资源请求也可能向对方发送敏感参数；只读不等于无数据外发、无费用或无风险。

每次调用校验当前身份、绑定 revision、描述指纹、输入 schema、目标资源、允许参数范围、数据目的地、配额和期限。共享/外部写操作走既有 ActionIntent/DispatchPermit；受限本地工作走 Task/Attempt 与工具记录；只读请求也留审计和资源使用记录。可自动执行预授权工具，不引入逐次人工审批轰炸。

MCP roots 是交互中提供的可用文件根信息，不能替代 OS 沙箱；服务若能越界读盘，发送一个 roots 列表不能阻止它。S06 需要本地文件的服务只获得获授权的具体挂载；远端服务拿到一个宿主 file:// 名字不会自动拥有文件字节，也不应因此泄露宿主路径。

44.5.5 目录变化、缓存及描述不能自授新权限

把 tools/list、资源目录和描述转换成公司/员工授权后的有界目录；结果分页，有效缓存带 endpoint/认证主体/绑定版本/描述指纹，不能跨公司复用包含私有说明或资源的结果。新规范提供缓存/列表变化机制，具体协议消息由 profile 处理，不把特定通知格式写死到内核。S05

远端目录出现新增工具时，先进入待批准候选，不自动追加权限。现有工具的说明、schema、目标或注解发生变化时，对受影响工具暂停新调用，重新核对资格/授权；无关工具可继续。不能因为名字没变就沿用旧批准。发现与刷新不会自动唤醒所有员工，仅确实影响可执行任务时产生去重工作信号。

descriptor_digest 固定的是所观察的接口描述，不证明远端程序实现没有改变。本地可锁定镜像/可执行物摘要；远端还要记录版本/发布信息、资格有效期和可信服务边界。无法证明的限制写入能力报告，不声称对任意远端恶意行为有完全防护。

44.5.6 MCP 服务状态、反向请求与秘密

共享一个配置不等于共享同一个进程、浏览器登录或远端业务状态。首版默认本地实例按公司、员工、使命与绑定 revision 分隔；不同公司不共用有状态工具实例。经证明确实无状态的服务可复用受控 transport/pool，但权限和缓存仍隔离。

本项目的 MCPConnection 是实现对象，不等于规范一定存在协议会话。对于新 profile，用显式业务 handle 跟踪浏览器/事务等状态；对于兼容 profile，原生 session ID 也仅限其连接语义。两者均不能作为管理员身份或直接复制到别家公司。旧 handle 是否可恢复需核对；不可恢复时只允许安全重建，不重发未知写动作。S03 S05

服务请求 sampling、elicitation、roots 扩张，或新规范返回需要额外输入的结果，都不能自动触发付费模型、同意授权或把秘密塞入参数。首版只支持声明的工具/资源最小能力；未支持的反向能力拒绝或形成受限的 input_required 阻塞，不把它显示成功。协议续交若未来支持，必须保存逻辑 ToolInvocation/Action 关系，不能将新 JSON-RPC request ID 当新业务幂等意图。S05

HTTP 认证使用所选服务支持的正常方式。OAuth 需要单独由管理员完成受控授权，运行时只持有面向正确受众、正确服务的凭据；不透传管理员 token、员工 token 或模型订阅 token 给第三方。SSRF 防护覆盖 metadata、重定向、URL 资源读取和最终解析的网络目标；TLS 校验不得默认关闭。显式登记的内网 MCP 可以按白名单例外放行具体地址/端口，不等于开放整个内网。S07

stdio 子进程只接收最小 env 白名单及它确实需要的 SecretRef，不继承主服务全部环境，不拥有 DB/QQ/容器引擎 socket。stdout 只按协议解析，日志走有界 stderr；本地服务同样属于不可信执行，不因官方 SDK 发起连接就与控制面处于同一信任等级。

44.5.7 结果、超时与费用

区分 transport/protocol 错误、工具 isError、缺少必要输入、结构不合格、业务结果未知及成功回执。HTTP 200、JSON 合法和工具文本“成功”不能直接变成任务验收通过。外部资源 URI、媒体内容、HTML、Markdown 和日志都先做类型/大小/权限检查；不自动访问返回的任意链接或加载外部图片。

工具可能部分产生效果后才报错。取消请求或关闭传输不证明远端停止；写操作结果未知按 C-RETRY 与 Action 核对，不换工具名/连接/session 重试来洗掉幂等记录。普通只读请求可在规定范围内重试，全部成本归原任务。

模型费、MCP 侧调用费、脚本计算/容器/存储分别计量。第三方 MCP 内部调用模型而无法限额时显示 billing_visibility=limited，不能宣称总美元严格硬封顶；资格不足的服务不得接要求硬限的使命。工具配额与速率限制是普通程序规则，不调用一个预算 Agent 再决定。

44.6 C-CAPABILITY：持久绑定、接班、撤权与休眠

44.6.1 EmployeeCapabilityBinding 的具体内容

新增版本化绑定：工作根与读写模式、公司共享资料范围、SkillRevision 列表、允许的脚本入口、MCPBindingRevision、工具/资源选择、出站目的地、环境资格、默认等待/回收政策。角色模板可以批量生成候选绑定，由人确认生效；不会每次新任务都重新配置。

绑定状态分 draft / approved / disabled / revoked，连接/挂载状态分 unprovisioned / connecting / available / unavailable / reconciling，接入资格另分 supported / limited / unsupported / unverified。批准可用不表示当前正在连接；已连接不表示有权调用；缺配置也不能画成正常工作。

新的公共 Skill 或 MCP 工具不会因“继承公共库”自动获得执行权限。首版继承是可审阅、版本固定的选中清单；新增条目作为待选项。允许维护者显式批量批准，不引入泛化 wildcard 未来自动放权。

44.6.2 换模型要交接环境，不只交接文字

接班包增加 capability_binding_ref、workspace_manifest、已用 Skill revision/指纹与加载清单、MCP 定义/绑定/描述指纹、正在执行的 ToolInvocation、适用费用责任、待重新连接状态。实际配置和文件快照在受控存储保存；接班包只保存允许的引用，不含 Secret 值、浏览器 Cookie、远端 bearer handle 或原生私有 session。

接班前先核对旧写者和工具结果。新模型先以只读 grant 读取所需冻结资料/技能；工具目录只返回当前允许范围，不在 validating 阶段偷偷启动一个有写权限的 MCP 进程。必要验证 scratch 的执行仍须已有的单独恢复授权。

运行时提交激活决定后，保持 activation_pending_environment；可信 supervisor 按新 incarnation/epoch 应用文件与工具权限，回执核对后才开始新业务。权限收缩与工具绑定撤销进入同一控制顺序。不能借恢复旧 Skill、MCP cache 或原生会话重新获得已撤销能力。

强制断线时，不依赖旧模型最后总结；程序根据持久绑定和使用记录生成最小环境清单。新模型可以按引用补读资料，但不默认重新索引全部源码。目标模型不支持某必需工具时明确阻塞，可使用预批准且真正等价的替代，否则等待而不假装迁移成功。

44.6.3 休眠与工具进程的生命周期

员工休眠不应维持付费推理；持久配置不删除。没在途工具和未决副作用时，本地 MCP 实例可在有界 idle grace 后排空关闭，下一次真实调用再启动；远程只关闭客户端连接不代表远端程序停止或数据清除。进程驻留、模型推理和业务进展分别显示与计量。

只读目录访问、技能缓存刷新和查看工具状态不唤醒模型。MCP 来的新通知先经普通程序验证、去重和任务相关性判断；无关日志/FYI 不生成推理任务。需要持续订阅的服务由人配置有期限、流量上限和数据范围的 Routine/连接政策，默认不保持无限消息采集。

工具在途时不得为节省内存直接杀掉并把结果记成失败。采用 draining/reconciling，按实际停止/隔离证据处理。主机重启和 MCP 崩溃后核对业务 handle、未结算用量和旧调用；无法证明安全就保持相关任务等待，不影响无关公司。

44.6.4 撤权、版本更新与 QQ 接管

工作区根、Skill/脚本、MCP 工具、秘密或外发目标撤销后，新调用按最新绑定拒绝；已加载资料、持有的句柄和进程权限另行回收。能力变化是当前授权的变化，不是永久从员工记忆删除其过去做过的工作。

工具临时不可达且自动重试有效时只留状态。真正缺少凭据、需批准新权限、无法隔离在途写者、或必要工具不能安全恢复时，才形成 HumanIntervention 并沿 QQ 主动接管通知规则去重外发。QQ 凭据与发送入口仍不属于员工可选 MCP 工具，不给普通员工 notify.send。

44.9 贯穿验证：同一个员工换模型后仍知道资料与工具在哪

固定规划、后端、前端、审查四岗位，采用可丢弃分页示例仓库。人预先确认共享接口资料、一个无脚本说明 Skill、一个带明确入口的受限脚本 fixture，以及一个本地/一个远程受控 MCP 测试服务；所有样本默认禁用，实际启用另行授权。

后端通过 workspace.search/read 定位代码，按需加载 Skill，调用已授权 MCP 查询测试资料，提交候选接口快照；前端直接读共享快照，不经规划员转发。中途切断后端模型，旧工具结果保留；新模型接管同一工号，从环境清单定位资料、技能和工具，核对后续写权限再继续。

注入来源 Skill 更新、同名项目技能、MCP 工具 schema 变化、调用超时、资源 URI 越界、权限收回和员工空闲。应观察：未批准更新不生效；旧工具描述不继续写；未知调用不重复；空闲不推理；真正需要人时只发一次受控 QQ 接管事项。审查员在冻结输入 + scratch 验证，不改候选后自批。
