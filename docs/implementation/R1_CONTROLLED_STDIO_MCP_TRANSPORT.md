# Controlled stdio MCP transport foundation

Updated: 2026-09-28. Transport and owner foundation began at Schema 40; package-source revisions are at Schema 44 and observation-intent fencing is at Schema 45.

## Implemented transport subset

`internal/mcptransport.StdioClient` implements a pinned MCP `2026-07-28` client over an `io.ReadWriteCloser` supplied by its process owner. It performs `server/discover`, `tools/list`, and `tools/call`; every request includes the per-request protocol version, client identity, and client capabilities. It does not send the legacy `initialize` handshake or fall back to another protocol version.

The client accepts only the tools capability, one-page tool listings, closed object input schemas with bounded primitive properties, and text-only tool results. It rejects malformed or uncorrelated JSON-RPC responses, server-initiated requests, non-text results, schema drift, private/unbounded tool input, and messages or results over their byte limits. Numeric bounds and enum matching use exact rational comparison, so integers beyond float64 precision cannot round through a limit or mismatch only because JSON spells an equal number as `1` or `1.0`. `tools/call` re-reads the tool list and compares its canonical SHA-256 to the approved digest before sending the call. Returned text is labeled `untrusted_stdio_mcp_text`.

Each in-flight request has a 30-second bound. If its context is canceled after the full request was written, the client sends `notifications/cancelled` with the original request ID, waits up to 250 ms for that notification write, then closes the stream. If the original request write does not finish within 250 ms, the client closes the stream without sending a cancellation for an unconfirmed request. The process owner remains responsible for stopping and waiting for the child process tree.

The wire contract follows the [official 2026-07-28 stdio transport specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/transports/stdio.mdx) and [transport overview](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/transports/index.mdx): newline-delimited UTF-8 JSON-RPC, request IDs, and process shutdown by closing stdin, waiting, then terminating only if needed.

## Current limits

`internal/mcptransport` remains only the wire client. `internal/mcpowner.Start` accepts only the concrete `runner.AppContainerSandbox`; its injectable launcher is package-private for tests. The production launcher requires deny-all networking and a complete bounded package-root inventory without links. It locks the package root, all directories and files against writes, rechecks the inventory after directory locks, and verifies every SHA-256 before process launch. The entry point must be pinned and included in `argv`, and path-like file arguments must also be in the manifest. A command digest and a canonical complete-package manifest digest bind the exact launch definition and package bytes. Startup checks server identity and the approved tool-schema digest. An empty approved schema digest permits qualification discovery only and cannot call a tool. Schema drift returns a typed error and stops the process.

The working directory must equal the pinned package root, keeping simple relative config names inside the complete locked inventory; absolute, traversal and Windows drive-relative paths outside it are refused.

Schemas 41–42 persist immutable command/package/schema qualification snapshots and append-only runtime status events. The Kernel records a snapshot only from the opaque observation produced by the concrete AppContainer owner after successful discovery, no tool call, and a clean process-tree stop. Generic metadata approval is separate from runtime approval. `AuthorizeStdioMCPToolCall` checks the current approved descriptor/version, employee binding, latest runtime status, schema digest and selected tool under the company guard. Schema drift and capability revocation append denying events. Schema 43 adds immutable per-session call intents and append-only `dispatching`, `completed`, and `outcome_unknown` events. A dispatch intent rechecks the active Worker binding and runtime qualification; duplicate provider call IDs are denied; bounded text results are stored with an untrusted-content boundary; unresolved calls cannot be replayed or completed late. Slice 54 connects this ledger to the fake-only `@mcp-v1` Worker path; real-provider mode remains denied. Slice 55 adds company-CAS-backed package revisions and authenticated import. ## Slice 59 runtime-observation boundary

The runtime observer is Windows-only and is not registered unless the operator explicitly sets `POLIS_MCP_RUNTIME_OBSERVATION_ENABLED=1`. It is unavailable when the concrete deny-all AppContainer sandbox cannot be created. The Workbench route requires its desktop session token; the UI enables it only for the latest imported revision with a current metadata-verified approval. The observer reads the package from company CAS, verifies the canonical manifest/file hashes, materializes the package under the isolated workspace and pins its source revision and manifest digest into the process specification. It performs discovery and tool listing only; it does not invoke `tools/call`. The owner must confirm process-tree stop before the opaque observation is recorded. Package import/revision updates revoke older runtime qualification. Runtime approval and Employee binding remain separate operations. In this implementation session the feature flag stayed off; no MCP program, model, external endpoint, or AppContainer/WFP host configuration was run.

Schema 45 reserves each Workbench request before any process start in an append-only observation intent ledger. A matching completed request returns its existing runtime record; a reserved or `outcome_unknown` request cannot run again. Startup converts abandoned reservations to `outcome_unknown`, never replaying package code. Package imports, observations, runtime approvals and Worker tool calls through result completion share a per-server advisory lock, and approval rechecks the latest immutable package revision. Normal shutdown revokes qualifications before removing temporary package roots. Startup revokes qualifications whose persisted workspace root differs from the current AppContainer root, including when runtime observation is disabled. For a shared sandbox, service shutdown quiesces WorkerSessions, cleans the observer, then closes the sandbox; the `serveWorkbench` caller retries cleanup once and returns joined errors if cleanup remains unresolved. Native Windows tests passed for AppContainer filesystem/loopback denial, Node snapshot placement and Job Object tree recovery; no WFP policy was installed. Slice 60 evidence: `evidence/development/r1-r3-implementation-validation-20260928-slice-60-mcp-observation-replay-and-windows-host/verification.md`.

The fixed profile does not include prompts, resources, subscriptions, server notifications, legacy protocol fallback, OAuth, or arbitrary MCP transports. The process owner does not make unverified tools executable or claim qualification merely because local fake-process tests pass.
