# R0.8 Capability Catalog Foundation

> Verified: 2026-09-22

## Delivered

The first capability-config slice is implemented on top of the existing Go/PostgreSQL/React control plane:

- `skill_revisions` stores immutable candidate metadata: publisher scope, package id, revision, display name, source reference, content digest, manifest and candidate status.
- `mcp_server_definitions` stores unverified stdio or streamable HTTP definitions, descriptor digest and safe connection metadata.
- Go kernel/control/read-store boundaries expose the catalog and candidate registration through the Company-scoped Workbench API.
- Group Settings now has a Skills/MCP tab with candidate registration forms and status lists.

## Safety boundary

Registration is not approval, connection, execution or capability binding. The UI and API do not scan arbitrary paths, install dependencies, execute Skill scripts, start MCP processes, call MCP endpoints, perform OAuth, or send QQ traffic. Candidate records remain `candidate`/`unverified` until a later explicit approval and qualification flow.

The new migration is schema 12. The kernel and Workbench read-store schema gates were updated together, avoiding the stale-sidecar failure mode that previously rejected schema 12 after migration succeeded.
