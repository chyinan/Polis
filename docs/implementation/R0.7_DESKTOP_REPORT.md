## Architecture

- `desktop/src-tauri/` is the Tauri v2 Windows host; `frontend/` remains the only React application and is loaded from bundled `frontend/dist` in packaged mode.
- Rust owns desktop data paths, a per-launch token, process supervision, dynamic loopback ports, single-instance lock, Windows Job Object ownership, tray events, diagnostics and shutdown/restart orchestration.
- Go remains the product/domain/control/runtime authority. PostgreSQL remains authoritative; no SQLite or second frontend was introduced.
- `polis.exe` is packaged as the Tauri external sidecar. The desktop host passes `POLIS_DSN`, `POLIS_BLOB_ROOT`, `POLIS_WORKBENCH_ADDR`, deterministic worker mode and the ephemeral session token.

## App-data layout

Default root: `%LOCALAPPDATA%\Polis\` (the test-only `POLIS_DESKTOP_DATA_ROOT` override is used only for isolated smoke fixtures).

| Directory | Purpose |
| --- | --- |
| `config/` | desktop preferences, lock, private database credentials |
| `data/` | desktop metadata |
| `postgres/` | private PostgreSQL cluster |
| `cas/` | authoritative product blob/CAS root |
| `logs/` | desktop, PostgreSQL and backend logs |
| `runtime/` | runtime metadata area |
| `temp/` | one-shot initdb password handoff and probes |

Product state is durable across restart. The session token and initdb password handoff are ephemeral; passwords are not sent to React or written to logs.

## Startup and first-run flow

1. Tauri acquires `config/desktop.lock` and starts the supervisor thread.
2. The supervisor resolves directories, detects/initializes PostgreSQL 18 with SCRAM authentication, creates the private `polis_runtime` role/database, waits for TCP readiness, and runs `polis migrate`.
3. It selects a free loopback port, starts the Go sidecar, and waits for authenticated `/healthz` rather than sleeping for a fixed duration.
4. Provider readiness is projected as `ready`, `authentication_required`, `runtime_missing`, `setup_required`, or `degraded` from the existing controlled manifest/binary/auth paths. No provider binary is downloaded or replaced.
5. React receives the endpoint/token through the typed Tauri bridge. First run shows the existing visual language with DB/backend/provider/event-stream status, Company name, workspace/project directory and the authoritative four-role roster: Planning, Backend, Frontend, Reviewer. Company creation uses the real Company API and persists the last company.
6. Subsequent startup restores the last Company; provider degradation does not prevent Workbench access.

## Backend and local API security

- `internal/desktop` adds a narrow token/CORS middleware. Desktop requests use `X-Polis-Desktop-Token`; EventSource uses a short-lived query token because native EventSource cannot set custom headers.
- Allowed desktop/dev origins are explicit (`tauri://localhost`, `http://tauri.localhost`, localhost Vite origins, and empty native-probe origin). Foreign origins and missing tokens are denied.
- `/healthz`, `/api/desktop/active-work`, and `/api/desktop/shutdown` are protected when desktop mode is enabled.
- `db.Migrate` continues to refuse non-`polis_r0_` databases; the diagnostic now includes only the rejected database name, never a DSN/password.

## Shutdown, tray and diagnostics

- Tray menu is wired for Open Polis, Runtime Status, Restart Local Services, Open Logs and Quit Polis.
- Main-window close is intercepted and hidden; Quit is separate and checks authoritative active Mission/WorkerSession state.
- Backend receives the formal shutdown request first; PostgreSQL uses `pg_ctl -m fast -w stop`; forced termination is logged only as a fallback.
- A Windows Job Object with kill-on-close owns child processes. Packaged smoke verified that forced desktop termination left zero `postgres.exe`/`polis.exe` processes.
- Desktop runtime status remains in the startup/diagnostics surfaces and is not injected as a global banner into business Workbench pages. Diagnostic text omits tokens, passwords and provider credentials.

## PostgreSQL and package

- The curated PostgreSQL 18 Windows runtime is sourced from the official EDB binary distribution during dependency setup and packaged as `postgres/bin`, `postgres/lib`, and `postgres/share`; unrelated pgAdmin/docs/include assets are excluded.
- Final installer: [Polis_0.7.0_x64-setup.exe](../../desktop/src-tauri/target/release/bundle/nsis/Polis_0.7.0_x64-setup.exe), 38,902,429 bytes.
- Final release executable: `desktop/src-tauri/target/release/polis-desktop.exe`, 9,756,672 bytes.
- NSIS `currentUser` packaging is configured; user app data is not deleted by the installer configuration.
- `code_signing = DEFERRED`; `auto_update = DEFERRED`.
