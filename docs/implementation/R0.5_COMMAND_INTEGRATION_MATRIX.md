# R0.5A Command Integration Matrix

> Verified 2026-09-16. This matrix records the existing implementation audit and the minimal command surface added by R0.5A. `frontend/` remains presentation authority; Go/PostgreSQL control/runtime remains behavior and data authority.

| UI action | Existing/reused frontend control | HTTP command | Application/domain handler | Authoritative mutation | Emitted event | Resulting read model |
|---|---|---|---|---|---|---|
| Submit Mission goal | Existing Company/Mission workbench surface, extended with one goal form | `POST /api/workbench/companies/{companyId}/missions` | `control.Service.CreateMission` → `Kernel.TXCreateMissionGoal` | Persist scoped Mission draft with title/goal and request-id receipt | `mission.create` with target and occurred-at | `GET .../overview` shows Mission draft/title/goal; activity shows creation |
| Start Mission | Existing Mission command area | `POST /api/workbench/companies/{companyId}/missions/{missionId}/start` | `control.Service.StartMission` → strict `Kernel.TXStartMissionCommand` → deterministic WorkerAdapter | `draft → active`, unique bootstrap task, WorkerSession lifecycle | `mission.start`, `worker.*` lifecycle events | overview shows active Mission, working bootstrap task, active Employee/WorkerSession, activity events |
| Stop/Cancel Mission | Existing Mission command area | `POST /api/workbench/companies/{companyId}/missions/{missionId}/cancel` | `control.Service.CancelMission` → WorkerAdapter stop proof → `Kernel.TXCancelMission` | stop active deterministic worker, then `active/paused → cancelled`; nonterminal tasks → cancelled | `worker.stopping`, `worker.stopped`, `mission.cancel` | overview shows cancelled Mission, stopped Employee/session and cancelled task; activity preserves ordered stop/cancel events |
| Pause/Resume | No formal product control added | none | Existing `TXSetPaused` is internal active/paused flip only | Not exposed in R0.5A | n/a | `pause_resume = DEFERRED` |

## Existing audit findings

- `internal/kernel` is the existing control/domain boundary; no parallel control plane is introduced.
- `cmd/polis serve` and `internal/workbench` were read-only before R0.5A.
- Existing `TXWrite` receipt deduplication is reused with stable request IDs; this is duplicate suppression, not distributed exactly-once.
- Stop uses the existing `TXBeginStop` → real `runner.Process.Stop` → `TXConfirmStopped` proof path. The deterministic adapter starts only a local helper process and `Kernel.Step`; it has no provider or external egress path.
- Every mutation is scoped to the configured Company and returns a typed command receipt or structured conflict/error; the frontend refetches authoritative overview/activity after success.
