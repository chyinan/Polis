# R2 PDF input foundation

> Updated: 2026-10-06, Slice 267. Bounded PDF text extraction and a strict subset of embedded-image input are implemented locally; complete page rasterization and the R2 format profile remain open and unqualified.

Direct `.pdf` uploads are stored as a deterministic `pdf_snapshot` gzip/tar package. The package contains the original PDF, a versioned extraction record, and extracted UTF-8 text when available. Its outer CAS digest binds all three; the internal directory manifest hashes each file. Revalidation rebuilds the package from the preserved PDF and requires byte-for-byte canonical equality.

The pinned parser is `github.com/giraffesyo/pdf@v0.7.0`. Intake limits the PDF source to 6 MiB, parses at most 40 pages sequentially, caps each decoded stream at 1 MiB, caps page operators/glyphs/forms/images, limits processing time, and stores at most 16 KiB of extracted text. Parser warning codes, page coverage, image-bearing pages, truncation, original SHA-256, extracted-text SHA-256, and parser version are stored in `pdf/extraction.json`. Parser errors are mapped to safe reason codes; uploaded document text is not echoed in errors.

Slice 265 added a bounded visual input for supported embedded PDF image objects. Slice 267 makes this path fail closed on incomplete data: it checks unpacked sample byte length using per-row padding before decoding, rejects stencil (`ImageMask`) images, and accepts only exact-length unpacked samples and `DCTDecode`. CCITT, JBIG2, JPX, and other filtered codecs are omitted until their completeness behavior is verified. It decodes at most eight objects per document, with a 1,000,000-pixel ceiling per object, a 256 KiB encoded PNG ceiling per object, and a 960 KiB total PNG ceiling. An `ImageCount` larger than the parser's returned image array marks the representation truncated and adds an omission warning. The canonical `pdf_snapshot` stores PNG bytes and extraction-record entries binding page number, parser image-array ordinal, pixel dimensions, image digest, page boxes, rotation, and four page-space placement points. The ordinal is one-based within this parser's page image array; it is not an original PDF object ID. Task context attaches selected PNGs as typed image inputs, and the immutable delivery receipt includes their page number, dimensions, path, and digest. The original PDF remains an explicit `representation_not_supported` exclusion.

These are intrinsic embedded-image objects, not complete page rasters or claims of restored visible appearance. The pinned parser does not expose or apply soft masks/transparency, color-key masks, or rendering intent, so the visible PDF appearance may differ. The representation does not composite vector text, page background, or multiple objects into a single page image; pages made from vector outlines and PDFs without a supported embedded image still have no visual input. Unsupported or over-budget images are recorded as omitted, and scanned pages receive no invented text or OCR. The parser record schema advances to `polis-pdf-extraction@3`; canonical verification continues to accept historical `@1` and `@2` snapshots byte-for-byte. New active Task/Worker delivery omits images from historical `@1`/`@2` snapshots, while persisted historical receipts remain verifiable. The frontend names the PDF limit and extraction boundary.
