# R2 PDF input foundation

> Updated: 2026-10-06, Slice 265. Bounded PDF text extraction and embedded-image input are implemented locally; complete page rasterization and the R2 format profile remain open and unqualified.

Direct `.pdf` uploads are stored as a deterministic `pdf_snapshot` gzip/tar package. The package contains the original PDF, a versioned extraction record, and extracted UTF-8 text when available. Its outer CAS digest binds all three; the internal directory manifest hashes each file. Revalidation rebuilds the package from the preserved PDF and requires byte-for-byte canonical equality.

The pinned parser is `github.com/giraffesyo/pdf@v0.7.0`. Intake limits the PDF source to 6 MiB, parses at most 40 pages sequentially, caps each decoded stream at 1 MiB, caps page operators/glyphs/forms/images, limits processing time, and stores at most 16 KiB of extracted text. Parser warning codes, page coverage, image-bearing pages, truncation, original SHA-256, extracted-text SHA-256, and parser version are stored in `pdf/extraction.json`. Parser errors are mapped to safe reason codes; uploaded document text is not echoed in errors.

Slice 265 adds a bounded visual input for supported embedded PDF image objects. The same pinned parser decodes at most eight objects per document, with a 1,000,000-pixel ceiling per object, a 256 KiB encoded PNG ceiling per object, and a 960 KiB total PNG ceiling. The canonical `pdf_snapshot` stores the PNG bytes and an extraction-record entry binding page number, image number, pixel dimensions, image digest, page boxes, rotation, and the image's four page-space placement points. Task context attaches selected PNGs as typed image inputs, and the immutable delivery receipt includes their page number, dimensions, path, and digest. The original PDF remains an explicit `representation_not_supported` exclusion.

These are extracted image objects, not complete page rasters. The representation does not composite vector text, page background, or multiple objects into a single page image; pages made from vector outlines and PDFs without a supported embedded image still have no visual input. Unsupported or over-budget images are recorded as omitted, and scanned pages receive no invented text or OCR. The parser record schema advances to `polis-pdf-extraction@2`; canonical verification continues to accept historical `@1` snapshots without rebuilding them as the new format. The frontend names the PDF limit and extraction boundary.
