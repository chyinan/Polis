# R0.9 Capability Binding

> Verified: 2026-10-31

## Delivered

This slice follows the R0.8 handoff: controlled local manifest import, format qualification, and employee capability binding.

- Migration `00013_r09_capability_binding.sql` stores one live binding per employee. Status is `draft`, `approved`, `disabled`, or `revoked`.
- `SKILL.md` import parses a closed frontmatter subset, rejects duplicate keys, aliases, unknown keys, and secret-bearing keys, and stores a content digest. The record stays `candidate`.
- A configured library root (`POLIS_SKILL_LIBRARY_ROOT`) can import only `skills/<id>/SKILL.md` and `mcp/<id>.yaml`. The scan refuses symlinks and does not read or run `scripts/`.
- An operator can approve or revoke a Skill revision. Only approved revisions can be placed in a binding. MCP definitions may be referenced while they remain unverified.
- Group Settings exposes import, approval, revocation, and binding. The catalog reports format status separately from execution and connection.

## Safety boundary

Binding approval is not connection or execution. The API does not scan an arbitrary caller-supplied path, install dependencies, execute Skill scripts, start MCP processes, call MCP endpoints, perform OAuth, or send QQ traffic. Qualification written by this slice is `executionStatus=unverified` and `connectionStatus=unprovisioned`.

The kernel and Workbench read-store gates now require schema 13.
