Design: app-server has a minimal isolated home and read-only fixture view inside a Linux PID/mount namespace. Native shell, external tools and delegation are disabled. Only scoped dynamic tools can modify the fixture through Polis. The native thread/turn IDs are correlation metadata; PG Employee/Task/attempt/epoch remain authoritative. A stopped process proof is required before replacing a writer. Recovery after loss of an un-reconciled real process stays blocked rather than using R0's fake-only automatic reassignment.

Fixture: retain `-0` versus `0` compatibility while adding explicit positive-number signs, then modify neighboring formatting to add an optional unit. Phase-one evidence and checkpoint explain the rejected zero-collapsing approach. Replacement receives a neutral bundle and a new thread, first in restoring/validating mode, and gains mediated write capability only after a control-side environment receipt. The independent compiled checker exercises behavior, including signed zero; keyword matching cannot pass it.

A single-worker mission verifies the employee tool loop. A separate disposable mission performs forced interruption after a committed partial checkpoint, then same-Employee handover. The shared allowance applies across both. The controller never calls native resume, thread/shellCommand or process/spawn. All in-flight failures with uncertain effects remain unknown and terminate the run.
