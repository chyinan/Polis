# REQ-29 authorized shared-file access audit

Updated: 2026-10-03, Slice 150. This source map leaves the frozen v0.4.5 design unchanged.

## Frozen requirements checked

Architecture section 3.1 describes REQ-29 as autonomous access to authorized workspaces and shared files, with read/write/snapshot separation and correct paths and versions. CAP-01–06 in section 44.10 cover self-discovery, path/link/special-file containment, shared versus private visibility, single-writer epochs, consistent reads, and ready/obsolete/GC snapshot handling.

## Current Worker boundaries

- Task input manifests are immutable, Mission-bound snapshots. `EnsureTaskInputManifest` binds the Mission inputs to a Task; `ProductTaskInputContext` reads only those CAS references under the current Task binding and verifies the prepared payload digest.
- A Worker can read its own whole Task workspace through `workspace_read`. Product writes replace that one bounded workspace using its expected digest and revision. The database supplies the WorkerSession/Task binding; callers do not select a filesystem path.
- Handover includes the current Task and its workspace. The recovery-only peer boundary snapshot and CAS manifest are generated by offline/probe recovery paths; they do not expose a general shared-file browser or authorize arbitrary CAS reads.
- The current product Worker tool registry has no operation to discover or read another Task's published Artifact. Peer messages carry bounded text and are not a file-transfer protocol. Thus a worker cannot autonomously inspect a teammate's published file without another worker copying its content into a message or current Task input.

## Concrete gap and bounded access rule

REQ-29 remains partial because the Worker has no read-only path to shared Mission work. The next slice should expose only published Task Artifacts belonging to the requester's same Company and active Mission. The Worker should discover them through a small bounded listing and read one by exact Artifact ID. Kernel should require the source Artifact to be `ready`, verify its CAS digest and recorded byte size, and return the immutable content version with its identity. The tool must derive requester Company/Mission from the active WorkerSession and Task in the database.

This access does not include another Task's private writable workspace, another Mission's files, a caller-supplied path or digest, missing/corrupt/invalidated content, or filesystem traversal. Existing write access remains limited to the current Task workspace with digest+revision compare-and-swap. Snapshot/recovery records remain separate from model-readable files. A new model-visible tool set needs its own exact fake-only surface; existing @4 and @7 fingerprints must remain unchanged, and no real-provider qualification is implied.

No implementation, schema, frozen catalog or external action changed in Slice 150. REQ-29 and CAP-01–06 remain open until the bounded shared-Artifact read path and applicable qualification evidence exist.
