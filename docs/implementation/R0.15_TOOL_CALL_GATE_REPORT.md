# R0.15 MCP `tools.call` Qualification Gate — Implementation Report

> Status: implemented (bounded stdio-first, 2026-11-07). **No external MCP/OAuth/network egress, remote/HTTP transport qualification, Skill script execution, QQ send, or provider turn was exercised.**

## Summary

R0.15 adds a deny-by-default gate for capability `tools.call` over registered MCP definitions. It is a **separate** surface from product/provider tool registries and from read-only `tools.list`/`tools.describe` (`callable=false` unchanged). Calls require explicit call qualification bound to binding + definition + tool handle + descriptor digest + policy revision; probe/descriptor reads and binding approval do not authorize execution.

## Delivered

- **Schema 16 (active):** `db/migrations/00016_r15_mcp_tool_call.sql`
  - `mcp_tool_call_qualifications`: explicit approval/qualification state (stdio-first, effect class, authorization ref, descriptor digest/policy binding).
  - `mcp_tool_call_receipts`: auditable bounded receipts with idempotency (`company_id,employee_id,handle,idempotency_key`), request/arguments digests, outcome/code, bounded result/error/process/egress observations.
- **Kernel gate:** `internal/kernel/kernel.go` schema gate bumped to 16.
  - `tool_call_policy.go`: request validation, canonical request/arguments digests, deny-by-default gate, structured codes. Argument validation uses a bounded dependency-free JSON Schema subset (`type` incl. integer, `properties/required/additionalProperties`, `items/minItems/maxItems`, `enum/const`, `allOf/anyOf/oneOf`, string/number bounds incl. RE2-safe `pattern`, in-document `$ref`/JSON Pointer to `#...` incl. `#/$defs/*` with cycle/depth limits, external `$ref` rejected, safe `format` whitelist with unknown formats treated as annotations); malformed descriptor schema => `SCHEMA_INVALID`, constraint violation => `ARGUMENTS_SCHEMA_VIOLATION`. Unsupported keywords are ignored (not full JSON Schema 2020-12).
  - `mcp_stdio_call.go`: controlled stdio MCP execution (`initialize` → `notifications/initialized` → `tools/call`) with restricted env (`probeEnvironment`), temp workdir, timeout, bounded result/stderr, no ambient secret injection beyond the restricted env.
  - `tool_call_tx.go`: `TXListMCPToolCallQualifications`, `TXUpsertMCPToolCallQualification`, `TXCallMCPTool`. Gate evaluated from approved binding, definition state, cached descriptor integrity/digest, and approved qualification; execution only after gate passes and stdio command is available. If `taskId` is provided, it must exist in the same company and be owned by the request employee (`core.OutOfScope`/`core.Denied`). If `sessionId` is provided (optional), request is fenced against `worker_sessions`/employee epoch/runtime incarnation and must match employee/task ownership and a non-stopped session state (`core.OutOfScope`/`core.Denied`/`core.StaleEpoch`); session fields are included in the request digest. Idempotent replay returns stored receipt when request digest matches; differing digest yields `IDEMPOTENCY_CONFLICT`. Denial receipts may include bounded structured `errorJson` detail for schema violations (`message`, `path`, `reason`; no argument values) and bounded `message` for other pre-execution denials where applicable.
- **Control:** `internal/control/command.go`, `service.go` add `CallMCPTool`, qualification list/upsert; default policy `r15-tools-call@1`.
- **Workbench HTTP:** `internal/workbench/http.go` adds `capabilities.tools.call`, `capabilities.tools.call-qualification`, `capabilities.tools.call-qualifications`, `capabilities.tools.call-receipts` (read-only list; excludes `resultJson`/`errorJson` bodies), `capabilities.tools.call-receipt` (read-only detail by receipt id; `resultJson`/`errorJson` bounded and best-effort redacted for sensitive keys). Company-scoped.
- **Tests:**
  - `internal/kernel/tool_call_policy_test.go`: deny-by-default matrix + schema-required denial (pure, no DB).
  - `internal/kernel/testdata/toolcallmcp/main.go`: local fake stdio MCP server (deterministic `tools/call` response; no network).
  - `internal/kernel/tool_call_integration_test.go`: `TestMCPToolCallGateAndExecution` — builds fake MCP, requires `POLIS_TEST_DSN` (dedicated disposable PostgreSQL, `polis_r0_`), verifies `CALL_NOT_QUALIFIED` denial, qualification approval, completed call, idempotent replay, `DESCRIPTOR_DIGEST_MISMATCH`.

## Safety properties

- Deny-by-default; no implicit upgrade from probe/describe/list/load/binding approval.
- Descriptor digest and cached schema/receipt integrity checked at gate/call time.
- Effectful/unknown calls require authorization ref (per current policy logic); read-class can be qualified explicitly.
- Stdio-only transport in this slice; remote/HTTP/OAuth is `TRANSPORT_NOT_QUALIFIED` / out of scope.
- Bounded I/O and receipts; no secret-bearing env expansion from model input.

## Known gaps / follow-ups

- Full JSON Schema validation for `pattern`/`$ref`/`format`/dependent schemas/unevaluated* etc. remains deferred; current subset is bounded and fail-open on unsupported keywords. `pattern`/regex support, if added, needs ReDoS-safe limits.
- Richer task/session/epoch binding for worker-context calls. `taskId`, when provided, is now checked for company-scope existence; deeper owner/epoch/fencing alignment can be added with existing session primitives.
- Workbench UI: read-only by default; no auto-execution. Any call-triggering UX needs separate design/authorization.
- Remote transports (Streamable HTTP/OAuth), network sandboxing profiles, and per-tool effect authorization tiers require separate qualification slices.
- Run `TestMCPToolCallGateAndExecution` on a dedicated `polis_r0_` PostgreSQL 18 DB and capture evidence under `evidence/development/r0.15-*` (no external egress).
